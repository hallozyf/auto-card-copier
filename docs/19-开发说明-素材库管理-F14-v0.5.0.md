## 2. 功能说明

### 2.1 F14-C · 数据外置与旧文件清理

- 校验清单（`.manifest.json`）与拷贝日志（`.copylog.txt`）默认写入
  `%APPDATA%\AutoCardCopier\manifests\<项目ID>.*`，素材目录**一个文件都不落**；
- 设置页新增开关「同时在素材目录写一份自描述文件」（`writeSelfDescribingFiles`，默认关闭）。
  打开后才写旧版的 `_manifest.json / _project.json / _copy.log`；
- 设置页新增「清理旧版元数据…」：
  1. 选目录 → **后台线程**扫描预览（不会卡界面）；
  2. 弹窗列出文件数、目录数与最多 20 个示例路径，**二次确认**（默认按钮为"取消"）；
  3. 只删除软件自己写过的三个文件名，其它文件（包括用户自己的 `notes.json`）一律不动；
  4. 不跟随符号链接/联接点，避免越界删除。

### 2.2 F14-A · 历史素材库导入

- 项目库页 →「导入素材目录」→ 选根目录 → 扫描识别 → 预览表（名称/日期范围/文件数/大小/是否已导入）→ 确认入库；
- 识别规则为**结构目录折叠**：年份目录（2025）、日期目录（2026-10-03）、`照片/视频/Photos/Videos/DCIM/CLIP`
  等结构目录不切分项目，自动折叠到上一级；折叠到扫描根时，只有根目录直接放素材才算一个项目；
- 重复导入自动跳过（按目标路径判定），再次扫描会标记"已存在，跳过"。

### 2.3 F14-B · 同日期追加

- 卡片页「追加到已有项目」：下拉框只列出**日期范围能覆盖或与本次素材重叠**的已有项目；
- **日期严格校验**：只要有任一文件落在项目日期范围之外，整批拒绝，并在结果区列出越界文件名与其拍摄日期；
- **同名冲突**交给用户三选一（弹窗，可勾选"本批剩余同类冲突都按此处理"）：

| 选择 | 实际动作 |
|------|----------|
| 覆盖 | 删除目标同名文件，写入卡上的文件 |
| 替换 | 旧文件改名为 `原名_旧_yyyyMMdd_HHmmss` 保留，再用原文件名写入 |
| 都要 | 旧文件不动，新文件加序号 `原名_2` |

- 目标文件已存在但**大小与 CRC32 完全一致**时视为重复，直接跳过、不打扰用户；
- 只校验新追加的文件，不动已有素材；追加成功后更新项目的文件数、来源（`append`）与最近校验时间。

### 2.4 F14-D · 跨天项目与两种布局

- 扫描到多个拍摄日期时，分组区顶部出现方式选择：**按天拆分**（默认，与 v0.4.0 相同）/
  **合并为一个项目**；
- 合并模式面板：项目名、**起始日期**、**终止日期**（下拉框只列出卡上实际存在的日期，默认取最早与最晚）、
  地点、类型，以及两种布局：

| 布局 | 目录结构 |
|------|----------|
| 合并放一起（flat） | `项目\照片\`、`项目\视频\`、`项目\其他\`（按设置页"子目录结构"决定更细的层级） |
| 一天一个文件夹（byday） | `项目\2026-10-03\照片\`、`项目\2026-10-04\视频\` … |

- 合并前校验：项目名不能为空、终止日期不得早于起始日期、**日期范围必须覆盖本次全部素材**
  （否则拒绝开始并提示示例文件名，引导改用"按天拆分"）；
- 项目记录新增 `startDate` / `endDate` / `source` / `importLayout` / `lastVerifiedAt`；
  项目库列表的日期列显示 `起 ~ 止`，详情区显示"跨天项目 · 一天一个文件夹 · 新建/历史导入/追加"；
- 追加到跨天项目时沿用项目自己的 `importLayout` 与日期范围校验。

### 3.1 顺手修掉的三个缺陷

1. **布局二在"不分类"模式下生成错误目录**：旧实现把"项目目录名的上一级目录名"当作类型，导致
   `项目\日期\项目名\`；现在无类型子目录时按素材类型命名，得到 `项目\日期\照片\`。
2. **多日分组时项目统计用了整张卡的数据**：`BuildProjectMeta` 原来取 `ScanResult` 的照片/视频数量与
   时间范围，多项目场景下每个项目都记成"整卡数量"；现在按 `CopyPlan.Items` 逐项统计。
3. **项目记录的 `shootDate` 带 `T00:00:00`**：列表与详情显示不美观，改为纯 `yyyy-MM-dd`。

## 4. 数据与兼容

- 项目记录字段只增不改：旧记录没有 `startDate/endDate/importLayout/source` 时，
  `IsMultiDay` 为 false、追加校验回退到 `shootDate`、布局回退 flat，行为与旧版本一致；
- 计划文件（F12 续传）在生成阶段就写入了**布局改写后的目标路径**，因此续传不需要重新判断布局；
- 素材目录不再被写入任何软件文件；如需跨机器自解释，可打开自描述文件开关。

## 6. 已知问题与限制

1. **合并模式的项目名不会自动带日期范围**：默认取命名模板（含最早日期），用户可改；
2. **未知拍摄时间的文件在布局二下不按日期归档**（保持项目根目录），因为没有可靠日期可用，软件不猜；
3. **追加不校验"已有文件是否仍在"**：只校验新文件（按批准范围），若用户手工删过素材，记录不会自动修正；
4. **项目库仍无 `index.json`**，项目数上万时列表加载会变慢（沿用既有决策）；
5. **`StartCopyAsync` / `ResumeAsync` 仍有约 40 行重复流程**（v0.3.0 起记录的重构项，未在本轮处理）；
6. 合并模式的日期只能从卡上实际存在的日期中选择，手填任意日期不支持（避免与素材不符）。

## 7. 请真机验证

1. **历史导入**：项目库页 →「导入素材目录」→ 选一个旧素材根目录，核对识别出的项目数、日期范围是否与目录结构一致；
2. **跨天合并**：插一张跨多天的卡 → 扫描 → 选「合并为一个项目」→ 起止日期默认是否等于卡上最早/最晚 →
   两种布局各跑一次，检查磁盘上的目录结构；
3. **追加**：拿一张与某已有项目日期相同的卡 →「追加到已有项目」→ 故意混入一个越界文件，确认整批被拒并列出文件名；
   再造一个同名文件，确认三种冲突动作符合预期；
4. **数据外置**：设置页关闭自描述文件 → 拷贝一次 → 确认素材目录里没有任何 `.json/.log`，
   而 `%APPDATA%\AutoCardCopier\manifests` 下有清单；再用「清理旧版元数据」处理一个旧目录（先看预览数字）。
