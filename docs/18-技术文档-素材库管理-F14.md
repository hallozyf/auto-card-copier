## 2. 数据存储设计（F14-C）

应用数据目录结构：

```
%APPDATA%/AutoCardCopier/
├─ settings.json          现有：设置
├─ history.json           现有：任务历史
├─ presets.json           现有：预设
├─ tasks/                 现有：断点续传计划
├─ projects/              项目记录：<projectId>.json（一项目一文件）
├─ manifests/             校验清单：<projectId>.json（新，替代素材目录里的 _manifest.json）
├─ index.json             项目索引（路径、日期范围、统计、修改时间），用于快速列表与重复导入判定
└─ logs/                  现有：日志（替代素材目录里的 _copy.log）
```

要点：
1. 一项目一文件，列表页只读 index.json，避免打开列表时读上千个文件；
2. 写入一律原子写（沿用 JsonStore.WriteAllTextAtomic）；
3. index.json 丢失或损坏时可从 projects + manifests 重建（提供"重建索引"命令）；
4. 可选开关 writeSelfDescribingFiles（默认 false）保留旧行为，供特殊场合使用。

迁移策略：
- 启动时或手动触发"迁移"：递归扫描指定根目录的 _project.json → 读入 → 写入 projects 与 index → 记录来源为"迁移"；
- 默认**不删除**素材目录里的旧文件；"清理"命令只删 _manifest.json、_project.json、_copy.log 三个文件名，且需二次确认；
- 迁移幂等：以"路径 + 文件修改时间 + 项目 Id"判定，重复迁移只更新不新增。

## 3. F14-A 历史导入：识别算法

```
ScanLibraryRoot(root, maxDepth)
  BFS 遍历目录（跳过隐藏、跳过软件自身目录）
  对每个目录：
     统计其中直接包含的媒体文件（按扩展名分类）与子目录
     若目录内媒体文件数 > 0 且（深度 == maxDepth 或无下级媒体目录）：
         记录为候选项目：路径、媒体数、大小、拍摄时间集合
     否则继续下探
  合并规则：候选项目 A 位于候选项目 B 之下且 B 无直接媒体文件 → 归入 B（"包含素材的最上层目录"）
  输出：候选项目列表（路径、日期范围、照片/视频数、大小）
```

- 拍摄时间来源：优先读 EXIF/容器时间（复用 F13 的 MediaTimestampReader），读不到回退文件时间；
- 大目录优化：先按文件修改时间粗排，仅对缩略图/预览需要的样本读文件头；导入本身只需要日期范围时可只读每个目录的最早与最晚若干文件；
- 可取消、有进度（沿用 ScanProgress 模式）；
- 重复导入判定：index.json 中存在相同路径且目录最后修改时间未变 → 默认跳过，可选择强制更新。

## 4. F14-B 追加：校验与执行

```
TryAppend(cardScan, targetProject)
  1. 读取目标项目的日期范围 [start, end]
  2. 对本次素材逐文件取拍摄日期：
       日期 < start 或 日期 > end → 加入越界列表
  3. 越界列表非空 → 拒绝追加（严格模式），界面显示越界文件与目标范围
  4. 计算目标目录布局（见第 5 节），逐文件生成目标路径
  5. 冲突处理：同名且大小相同 → 计算哈希比对：
       相同 → 跳过（计入"已存在"）
       不同 → 目标名追加 _2、_3 …
  6. 复用 CopyEngine 拷贝 + VerifyService 仅校验新文件
  7. 更新项目记录：文件数、大小、日期范围、校验状态、更新时间；写一条"追加"任务历史
```

注意：
- 严格模式（整批拒绝）是本需求批准后的默认行为；若后续希望"自动剔除越界文件"，只需新增一个模式开关，不影响数据结构；
- 追加不移动、不覆盖任何已有文件；写入仍走"临时文件 + 校验 + 原子改名"。

## 5. F14-D 跨天项目与两种布局

项目记录新增字段：StartDate、EndDate（单日项目两者相同）、ImportLayout（合并/按天）。

布局生成规则：

```
布局一（合并放一起）：
  <项目目录>/照片/...
  <项目目录>/视频/...
  <项目目录>/其他/...

布局二（一天一个文件夹）：
  <项目目录>/2026-10-03/照片/...
  <项目目录>/2026-10-03/视频/...
  <项目目录>/2026-10-04/照片/...
```

- 实现方式：CopyPlanBuilder 增加"按拍摄日期 + 媒体类型"计算子目录的能力（纯内存，不访问文件系统）；
- 与 F13 的关系：扫描后界面提供"按天拆分（现有）"与"合并为一个项目"两种模式，前者复用现有逻辑，后者生成单个 ProjectGroupRequest 但日期范围为整段；
- 追加时布局沿用目标项目已有的 ImportLayout 与日期分段，保证新增文件落在同一天的目录里。
