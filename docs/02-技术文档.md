1. 使用传统（非 SDK 风格）csproj，TargetFrameworkVersion = v4.8；
2. 设置 FrameworkPathOverride 指向 C:\Windows\Microsoft.NET\Framework64\v4.0.30319；
3. 设置 PlatformTarget = x64（避免与 AMD64 参考程序集产生 MSB3270 架构不匹配告警）；
4. 用 MSBuild.exe 构建，XAML 正常编译，**零警告零错误**，产物可直接运行。

> 说明：把参考程序集指向系统运行时目录属于本环境的变通做法，编译器只读取其公共元数据，不影响运行结果。该设置集中在 Directory.Build.props 中，便于日后安装正式 SDK / Targeting Pack 后一键移除。

### 2.4 设计原则（硬性）

1. **单一文件单一职责**：单个 .cs 文件原则上不超过 400 行；超过即拆分（partial 类或子服务）。
2. **UI 与 I/O 严格分离**：所有耗时操作在后台线程（Task.Run / async），UI 线程只做绑定更新；进度通过 IProgress 上报并节流（≥ 100 ms 或 ≥ 1% 变化才刷新）。
3. **零第三方依赖**：不引入任何 NuGet 包；需要的算法（CRC32 等）自行实现并单测。
4. **可测试性**：Core 不引用任何 WPF 类型（PresentationFramework 等），保证可在控制台测试中被直接调用。
5. **失败必留痕**：任何 catch 都必须记录日志并向上返回结构化结果（Result 对象），禁止吞异常。

## 4. 功能实现方案（F01–F16）

> 每一节对应需求文档中的一个功能，给出：**涉及技术 → 实现路径 → 关键细节 → 主要风险**。

### F01 存储卡自动识别与监听

- **涉及技术**：Win32 窗口消息 WM_DEVICECHANGE（0x0219，DBT_DEVICEARRIVAL 0x8000 / DBT_DEVICEREMOVECOMPLETE 0x8004，DBT_DEVTYP_VOLUME 0x0002）通过 HwndSource.AddHook 接收；DriveInfo 枚举；GetVolumeInformation 取卷标、文件系统、卷序列号；GetDiskFreeSpaceEx 取容量；System.Management（WMI）仅在需要时查询物理盘与总线类型。
- **实现路径**：
  1. 主窗口初始化时获取 HwndSource，注册 WM_DEVICECHANGE 钩子；
  2. 收到卷变化消息后启动 800 ms 防抖定时器，到期执行一次全量刷新（消息不携带盘符，必须重新枚举）；
  3. 另有 3 秒轮询兜底，覆盖不发消息的读卡器；
  4. 刷新流程在后台线程：枚举 DriveInfo，跳过光驱与无根目录的卷，读取卷信息与根目录特征目录（DCIM、M4ROOT、AVCHD、XDROOT、PRIVATE）；
  5. 卡片判定规则：命中特征目录且不是系统盘；或卷标命中相机卡常见命名；或 DriveType=Removable 且容量大于 0；
  6. 生成卡片指纹（卷序列号 + 卷标 + 总容量，稳定且不受盘符影响），用于识别同一张卡与防重复导入；
  7. 通过事件总线把变更推给视图模型，UI 增量更新列表。
- **关键细节**：Win32 消息回调中只投递事件，绝不做 I/O；卡片"消失"与"出现"都要处理；同一张卡换盘符后仍应识别为同一张卡。
- **主要风险**：CFexpress 读卡器报成固定磁盘 → 用特征目录 + 卷标多重判定；USB 集线器导致一次插入触发多次消息 → 防抖 + 指纹去重。

### F02 卡片内容扫描与分析

- **涉及技术**：Directory.EnumerateFiles 手动递归（不用 SearchOption.AllDirectories，便于跳过忽略目录并在权限异常时继续）；FileInfo 读取 Length 与 LastWriteTimeUtc；扩展名分类表；最小 EXIF 解析器（读 TIFF 头与 IFD0 的 Make 0x010F、Model 0x0110，仅解析前 128 KB）识别相机型号。
- **实现路径**：
  1. 从特征目录（或卡根）开始递归，遇到忽略目录（System Volume Information、.Trashes 等）直接跳过；
  2. 按扩展名归类：照片（CR3、CR2、NEF、ARW、RAF、DNG、JPG、JPEG、HEIC、TIF）、视频（MP4、MOV、MXF、BRAW、R3D、MTS、M2TS）、其他；
  3. 累计数量、字节数、最早与最晚修改时间；
  4. 机型推断：最多读取 20 个照片文件头部，命中即停止；失败则显示"未知"；
  5. 每 200 ms 通过 IProgress 上报进度；
  6. 结果封装为 ScanResult 返回并缓存，供拷贝计划复用。
- **关键细节**：文件一律以 FileShare.ReadWrite 与 Delete 打开（只读、不锁卡）；枚举中的 IO 异常按文件跳过并计数，最后提示"跳过 N 个无法访问的文件"；绝不写入卡片。
- **主要风险**：数十万文件时枚举耗时长 → 后台线程 + 可取消；卡在扫描中被拔 → 捕获 IO 异常并中止，不崩溃。

### F03 项目自动命名与目标路径规划

- **涉及技术**：自研轻量模板引擎（StringBuilder 单遍扫描占位符）；Path.GetInvalidFileNameChars 清洗；Path.Combine 拼接；PathUtil 长路径包装；目录冲突检测。
- **实现路径**：
  1. 从设置读取命名模板，默认按"年份 / 日期_类型_地点"生成；
  2. 解析占位符（yyyy、MM、dd、HH、mm、type、location、camera、photographer、card、seq），未识别的占位符原样保留并在界面提示；
  3. 逐段清洗：非法字符替换为下划线、去掉首尾空格与点、删除控制字符、按段长度截断（整路径不超过 200 字符）；
  4. 组合为目标相对路径，再与目标根组合为完整路径；
  5. 冲突处理：目标已存在时按策略自动追加序号、合并进已有目录或询问用户；
  6. 最终路径合法性验证（Path.GetFullPath 不抛异常、盘根存在且可写）。
- **关键细节**：中文、空格、emoji 地名直接支持；模板变更不影响历史项目；同一张卡重复导入时通过指纹提示。
- **主要风险**：模板写错导致路径异常 → 生成后立即校验并在界面预览真实路径；层级过深 → 限制段数与总长度。

### F04 高性能并行拷贝引擎

- **涉及技术**：Task 与 SemaphoreSlim 限流；FileStream（FileOptions.Asynchronous 与 SequentialScan）分块读写；小文件走 File.Copy 快路径；临时文件 + 原子改名；File.SetLastWriteTimeUtc 保留时间戳；Interlocked 计数与 1 秒滑动窗口速率；CancellationTokenSource 与 PauseToken 实现取消与暂停；GetDiskFreeSpaceEx 空间预检。
- **实现路径**：
  1. 由 ScanResult 生成 CopyPlan：每个文件给出源路径、目标路径、字节数、动作（拷贝或跳过）；
  2. 预检：目标根可写、可用空间大于源总量乘以 1.05、源文件可读；
  3. 创建目录结构（照片 / 视频 / 其他，可选再分 RAW 与 JPG）；
  4. 并行执行（默认 4 并发）：写入同目录临时文件（.acctmp 后缀）→ 校验长度 → File.Move 覆盖为目标名（同卷原子）；
  5. 每完成一个文件更新计数、写任务流水、按节流上报进度；
  6. 汇总结果：成功数、失败清单（含错误码与消息）、总耗时与平均速度。
- **关键细节**：暂停在文件边界与块边界生效；取消时删除临时文件，保证目标目录不出现半截文件；时间戳在改名后设置；目标为网络路径时并发不宜过高（SMB 高并发反而更慢），并发数可配置。
- **主要风险**：读卡器在小文件场景随机读性能差 → 小文件并发、大文件分块；网络抖动 → 异常分类重试（最多 3 次，退避 1 秒、3 秒、9 秒）。

### F05 数据完整性校验

- **涉及技术**：CRC32（多项式 0xEDB88320 查表实现）、SHA256（System.Security.Cryptography）、抽样哈希（首 1 MB + 中点 1 MB + 尾 1 MB + 长度）、流式比较（源与目标各开缓冲交替读取）。
- **实现路径**：
  1. 按设置档位选择策略：不校验 / 仅大小 / CRC32 全量 / SHA-256 全量 / 大小 + 抽样；
  2. 逐文件校验：先比长度，再按档位计算哈希并比较；
  3. 小于 3 MB 的文件抽样退化为全文件哈希；
  4. 记录每个文件的校验结果、耗时与失败原因；
  5. 汇总为 VerifyReport 驱动界面展示（通过数、失败清单、一键重拷）。
- **关键细节**：哈希计算顺序读盘（单线程串行），避免并行随机读导致吞吐下降；校验范围可限定为照片或视频；超过 4 GB 的文件使用 long 长度并避免整文件读入内存。
- **主要风险**：校验耗时接近拷贝时长 → 默认"大小 + 抽样"，界面明确标注各档位的可靠性差异；卡出现坏块 → 记录偏移与错误码并提示卡片可能存在问题。

### F06 校验清单与拷贝报告

- **涉及技术**：DataContractJsonSerializer（缩进可读 JSON）；CSV 导出（UTF-8 带 BOM 兼容 Excel）；先写临时文件再改名的原子写入。
- **实现路径**：
  1. 拷贝与校验完成后组装 Manifest（项目、源卡、文件列表、汇总）；
  2. 写 _manifest.json 与 _project.json 到项目目录（临时文件 + 改名）；
  3. 同时写本地项目库与索引；
  4. 写 _copy.log（本次任务可读日志）；
  5. 界面提供复制摘要（文本）与导出 CSV。
- **关键细节**：同一套模型用于写入与读取，保证"能写就能读"；文件列表使用相对路径（跨机器可用）；校验档位写入清单，避免日后误判强度。
- **主要风险**：项目目录不可写 → 降级为只写本地并在界面提示；清单被外部修改 → 提供"重新校验项目"逐文件核对。

### F07 拍摄项目元数据管理

- **涉及技术**：数据模型与 DataContract 特性；ProjectRepository 增删改查；双写（本地库 + 服务器 _project.json）；拍摄时间范围推断（取素材最早与最晚文件时间）。
- **实现路径**：
  1. 拷贝开始时创建项目草稿（地点、类型、备注来自界面，其余自动推断）；
  2. 拷贝成功后落库：本地 projects 目录下的 id.json 与服务器 _project.json；
  3. 编辑任一字段 → 更新 updatedAt → 双写；
  4. 删除记录只删本地库（不删磁盘素材），需二次确认；
  5. 拍摄类型与地点来自 presets.json（可自定义、自动记忆最近使用）。
- **关键细节**：项目 id 与目录名解耦（改名不破坏关联）；同一张卡重复导入时以指纹提示；服务器 _project.json 作为跨机器的事实来源。
- **主要风险**：本地库与服务器副本不一致 → 提供"从服务器重建项目库"并保留更新时间较新的一份。

### F08 项目库管理与检索

- **涉及技术**：内存索引（List 与 LINQ 谓词过滤）；ObservableCollection 与 CollectionViewSource；ListView 虚拟化（IsVirtualizing 与 Recycling）；搜索输入 200 ms 防抖。
- **实现路径**：
  1. 启动加载 index.json，失败则扫描 projects 目录重建；
  2. 绑定列表，默认按拍摄日期倒序；
  3. 过滤条件（时间范围、地点、类型）与关键词组合为单一谓词在内存执行；
  4. 统计摘要按当前筛选结果实时计算；
  5. 行内操作（打开目录、复制路径、重新校验、编辑、删除记录）。
- **关键细节**：500 条规模无需数据库；列表项使用轻量模板，滚动依靠 UI 虚拟化；"打开目录"通过 explorer 选中进程启动。
- **主要风险**：索引文件损坏 → 自动重建；项目过多导致启动慢 → 惰性加载 + 后台刷新。

### F09 任务历史与日志审计

- **涉及技术**：自研 FileLogger（StreamWriter 加锁、按天切分、单文件 10 MB 上限）；TaskJournal 写 JSONL（一行一事件）；历史记录持久化在本地库。
- **实现路径**：
  1. 任务开始写 started 事件（卡片指纹、目标、计划文件数）；
  2. 关键节点与失败写 file 事件（避免日志爆炸）；
  3. 结束写 completed 或 failed 事件（耗时、平均速度、成功与失败数）；
  4. 历史页按时间倒序展示，可按结果筛选；
  5. 启动时按保留天数清理过期日志。
- **关键细节**：日志写入失败绝不抛出（降级为内存缓冲）；所有异常记录类型、消息与堆栈摘要；日志目录可在界面一键打开。
- **主要风险**：长任务日志膨胀 → 单文件上限 + 只记关键事件；多线程并发写 → 加锁 + 缓冲。

### F10 安全格式化与清空卡片

- **涉及技术**：WMI 关联（Win32_DiskDrive → Win32_DiskDriveToDiskPartition → Win32_LogicalDiskToPartition）取得盘符对应的物理盘号与 InterfaceType；CreateFile 与 DeviceIoControl（FSCTL_LOCK_VOLUME、FSCTL_DISMOUNT_VOLUME）预处理卷；Process 调用系统 format.com（隐藏窗口、重定向输出、120 秒超时）；GetVolumeInformation 复核结果。
- **硬性护栏（不可配置，代码级强制）**：
  1. 盘符不得等于系统盘（%SystemDrive%）；
  2. 盘符对应物理盘不得是系统盘所在物理盘；
  3. 物理盘 InterfaceType 必须为 USB（或 MediaType 含 Removable），排除内置 NVMe 与 SATA 盘及虚拟盘；
  4. DriveType 不得为 Network、CDRom、NoRootDirectory；
  5. 必须存在本次卡片指纹的成功拷贝且校验通过记录；
  6. 该盘上不能有本软件进行中的任务。
- **实现路径**：
  1. 取卡片指纹 → 查询最近一次成功任务 → 不满足护栏直接禁用按钮并显示原因；
  2. 用户确认（默认弹窗，可设置自动倒计时）；
  3. 释放本软件持有的句柄，锁定并卸载卷（失败仍继续尝试 format.com 并给出提示）；
  4. 调用 format.com 快速格式化（/Q），文件系统按设置（默认沿用原文件系统），卷标默认沿用原卷标；
  5. 复核：重新读取卷信息（文件系统、卷标、可用空间是否接近总容量）；
  6. 记录日志与历史，提示可以安全拔卡。
- **"清空卡片"替代方案**：递归删除特征目录下的文件但保留目录结构，进度可见、可取消。
- **主要风险**：卡被资源管理器或其他软件占用导致格式化失败 → 明确提示关闭资源管理器窗口或退出相机厂商软件后重试；FAT32 单文件 4 GB 限制 → 卡片大于 32 GB 且选择 FAT32 时显式警告；写保护开关 → 检测并提示。

### F11 多目标备份

- **涉及技术**：TargetEndpoint 抽象（路径、并发策略、独立进度）；CopyEngine 支持一个源扇出多个目标；结果汇总判定。
- **实现路径**：
  1. 计划阶段为每个目标生成一份 CopyPlan（相对路径一致）；
  2. 执行策略默认"主目标先行、副目标随后"（避免同一物理磁盘磁头竞争），可切换为并行；
  3. 每个目标独立进度与校验结果；
  4. 汇总：全部成功为成功；部分成功标红并提供单目标重试。
- **关键细节**：副目标可为 UNC 路径；副目标离线不阻塞主目标；两目标指向同一物理磁盘时给出性能提示。
- **主要风险**：误把副目标指向主目标同一目录 → 启动时校验并拒绝；副目标空间不足 → 计划阶段预检并跳过副目标（记录原因）。

### F12 断点续传与失败重试

- **涉及技术**：计划持久化（任务 JSON）；恢复时文件存在性与长度比对；网络重连循环（15 秒间隔，最长 30 分钟，可手动取消）。
- **实现路径**：
  1. 任务开始写 _copy.plan.json（含文件清单与状态）；
  2. 每完成一个文件更新状态（批量写入以避免频繁 I/O）；
  3. 软件启动时扫描未完成任务并提示继续、放弃或查看详情；
  4. 恢复时按策略（CopyIfNewer、Force、Skip）决定跳过或重拷；
  5. 单文件失败重试 3 次（退避 1 秒、3 秒、9 秒），仍失败则记入失败清单并继续其他文件。
- **关键细节**：任务状态机（Pending → Planning → Copying → Verifying → Completed / Failed / Cancelled / Paused）；断电恢复依赖计划文件而非内存状态。
- **主要风险**：目标文件被外部修改导致长度一致但内容不同 → 恢复时对长度一致的文件做抽样校验；计划文件损坏 → 视为新任务并保留原文件。

### F13 设置中心

- **涉及技术**：AppSettings 模型与 SettingsStore（默认值填充、字段校验、损坏自愈、原子写入）；WPF 双向绑定与防抖保存；导入导出 JSON。
- **实现路径**：
  1. 启动读取 settings.json，缺字段补默认值，非法值回退并记日志；
  2. 解析失败时把原文件改名为 settings.json.bad 并重建默认配置；
  3. 界面按六个分组展示，改动即时生效（需重启的项明确标注）；
  4. 保存采用"写临时文件 + 改名"，并做 500 ms 防抖。
- **关键细节**：schemaVersion 支持后续迁移；提供恢复默认设置与打开配置目录。
- **主要风险**：用户手工编辑配置写错 → 自愈并在界面提示；改动影响运行中的任务 → 只对新任务生效并提示。

### F14 系统托盘与通知

- **涉及技术**：System.Windows.Forms.NotifyIcon（程序集系统自带，仅此一处引用 WinForms）；ShowBalloonTip 显示系统通知；System.Drawing 动态绘制托盘图标（避免图片资源）；Window.Closing 拦截隐藏。
- **实现路径**：
  1. 启动创建 NotifyIcon 与右键菜单（显示主界面、暂停、弹出卡片、退出）；
  2. 主窗口 Closing 时若开启最小化到托盘则取消关闭并隐藏，首次隐藏给气泡提示；
  3. 任务完成或失败调用 ShowBalloonTip，可选播放系统提示音；
  4. 真正退出走应用级标志，确保 NotifyIcon 释放。
- **关键细节**：托盘图标在退出路径（含异常退出）中释放；通知内容不超过两行。
- **主要风险**：托盘图标残留 → 在 Application.Exit 与 AppDomain 卸载事件中都调用 Dispose；通知被"专注助手"屏蔽 → 同时播放提示音。

### F15 现代化界面与交互

- **涉及技术**：WindowChrome 自定义标题栏；资源字典实现主题切换（DynamicResource）；Segoe Fluent Icons 字体图标；Storyboard 与 VisualStateManager 做悬停与进度动画；ListView 虚拟化；app.manifest 声明 PerMonitorV2 DPI 感知。
- **实现路径**：
  1. 定义基础资源字典：颜色与圆角、字体、控件样式（按钮、输入框、卡片、进度条、列表项）；
  2. 主题字典（Light 与 Dark）通过合并字典动态替换，实现运行时换肤；
  3. 主窗口使用 WindowChrome，标题栏区域 CaptionHeight 支持拖动与双击最大化，按钮自绘；
  4. 左侧导航用 RadioButton 加样式实现，右侧内容区用 ContentControl 加 DataTemplate 切换；
  5. 耗时操作绑定命令（CanExecute 控制可用性），进度区绑定 IProgress 上报的数据。
- **关键细节**：避免给大量元素加 DropShadowEffect（软件渲染开销大），改用边框与背景层次；字体统一微软雅黑与 Segoe UI；控件尺寸用相对布局，不硬编码像素。
- **主要风险**：高 DPI 下图标与文字错位 → 矢量图标字形 + 相对布局，在 100%、125%、150%、200% 下逐一验证；主题切换资源未刷新 → 全部使用 DynamicResource。

### F16 便携部署与运行环境

- **涉及技术**：传统 csproj 输出到 build/out；app.manifest（DPI 感知、longPathAware、asInvoker）；免安装运行；开机自启写入 HKCU 的 Run 键。
- **实现路径**：
  1. 构建脚本输出到 build/out（exe、少量 dll、manifest）；
  2. 程序目录只读时自动把数据目录切到 %APPDATA%；
  3. 首次运行向导：选择目标根、数据目录、默认拍摄类型；
  4. 开机自启写入 HKCU 下的 Software、Microsoft、Windows、CurrentVersion、Run 路径，关闭时删除。
- **关键细节**：除自启项外不写注册表；不申请管理员权限；升级只需覆盖文件。
- **主要风险**：程序放在只读目录（如 Program Files）导致数据无法写入 → 启动时探测写权限并自动回退到 %APPDATA%，同时提示。

## 6. 可能的缺陷（Bug）与预防措施

| 编号 | 可能出现的缺陷 | 根因 | 预防与规避措施 | 验证方式 |
|------|----------------|------|----------------|----------|
| B01 | CFexpress 或 XQD 卡未被识别为卡片 | 读卡器把卡报告为固定磁盘 | 特征目录、卷标、容量多重判定；提供手动添加盘符入口 | 真机插卡测试 |
| B02 | 把系统盘或 NAS 误判为卡片 | 判定条件过宽 | 排除系统盘与网络盘；判定逻辑写单元测试 | 单元测试与手工 |
| B03 | 误格式化非目标盘 | 盘符与物理盘映射错误或护栏缺失 | 六条硬性护栏 + 卡片指纹绑定 + 二次确认 | TU-19 至 TU-21 |
| B04 | 拷贝后文件损坏却显示成功 | 只比大小、无内容校验 | 默认"大小 + 抽样哈希"，可选 CRC32 或 SHA-256 | TU-10 至 TU-12 |
| B05 | 目标目录出现半截文件 | 直接写目标文件名，中断即残留 | 临时文件 + 原子改名；取消时删除临时文件 | TU-08 |
| B06 | 中文文件名乱码 | 编码处理不当 | 全流程使用 Unicode API；CSV 导出带 BOM | TU-26 |
| B07 | 超长路径拷贝失败 | MAX_PATH 限制 | 统一经 PathUtil 加长路径前缀；清单中保存原始相对路径 | TU-25 |
| B08 | 网络断开导致任务直接失败 | 未做异常分类 | IO 异常分类 + 自动暂停重连 + 断点续传 | TU-17、TU-18 |
| B09 | 长任务期间界面假死 | UI 线程执行 I/O | 所有 I/O 移入后台线程，进度节流上报 | 拷贝期间操作界面 |
| B10 | 内存占用暴涨 | 一次性读入大文件、事件未解绑 | 流式分块读写；窗口关闭时解绑事件 | TU-27 |
| B11 | 拍摄时间变成拷贝时间 | 未显式设置时间戳 | 拷贝后设置最后写入时间与创建时间 | TU-06 |
| B12 | 目标空间不足导致中途失败 | 未做预检 | 计划阶段预检（源总量乘以 1.05） | TU-09 |
| B13 | 同一张卡被重复导入 | 无卡片指纹 | 指纹（卷序列号 + 卷标 + 容量）去重与提示 | 手工重复插卡 |
| B14 | 格式化失败且原因不明 | format.com 输出被丢弃 | 重定向并解析输出，映射为可读原因（占用、写保护、不支持） | TU-22 |
| B15 | 卡片拔出后软件崩溃 | 未捕获卡上 I/O 异常 | 卡上 I/O 全部包在异常处理内；拔卡事件触发任务暂停 | TU-18 |
| B16 | 配置损坏导致启动失败 | 直接反序列化 | 自愈：备份坏文件 + 默认值 + 提示 | TU-23 |
| B17 | 托盘图标残留 | NotifyIcon 未释放 | 退出路径统一释放，异常退出也处理 | 退出后检查托盘 |
| B18 | 主题切换后部分控件仍是旧色 | 使用了 StaticResource | 全部改用 DynamicResource | 切换主题逐页检查 |
| B19 | 高 DPI 下界面错位 | 硬编码像素与固定宽高 | 相对布局 + 矢量图标 + manifest 声明 PerMonitorV2 | 四种缩放实测 |
| B20 | 项目库与服务器不一致 | 双写失败或人工改动 | 提供"从服务器重建"；以 updatedAt 较新者为准 | TU-16 |
| B21 | 并发过高导致速度反而下降 | 机械盘与网络盘随机寻道 | 并发数可配置，默认 4；网络目标建议 2 至 4 | 性能对比测试 |
| B22 | 日志无限增长 | 未做滚动与清理 | 按天切分、单文件上限、按保留天数清理 | 长跑测试 |

## 8. 编码规范与版本控制工作流

### 8.1 编码规范

| 项目 | 规范 |
|------|------|
| 命名 | 类型与方法 PascalCase；私有字段下划线加 camelCase；接口 I 前缀；异步方法 Async 后缀 |
| 文件组织 | 一个文件一个主要类型；单文件不超过约 400 行；按功能分目录 |
| 注释 | 类型与公开成员必须有中文 XML 文档注释；复杂算法在关键行用中文注释解释"为什么" |
| 错误处理 | 禁止空 catch；异常必须记录日志并转换为结构化结果返回 |
| 线程 | 耗时操作必须异步；共享状态用锁或 Interlocked；禁止在 UI 线程做 I/O |
| 依赖 | 禁止引入第三方包；需要的算法自研并补单元测试 |
| 资源 | 所有 IDisposable 使用 using；事件订阅在生命周期结束时解绑 |

### 8.2 版本控制工作流

| 项目 | 约定 |
|------|------|
| 工具 | 便携 MinGit（tools 目录下的 git/cmd/git.exe），未污染系统 PATH |
| 仓库 | 本目录即仓库根；.gitignore 排除 bin、obj、build/out、tools/git、日志与运行数据 |
| 分支 | main 为主分支；较大功能使用 feature 分支，完成后合并 |
| 提交粒度 | 每完成一个开发步骤提交一次 |
| 提交信息 | 类型(范围): 说明，例如 feat(copy): 支持并行拷贝、fix(format): 修正护栏判定、docs: 新增技术文档 |
| 里程碑 | 每个里程碑结束打 tag（v0.1-m1 起），并更新 CHANGELOG.md |
| 提交前 | 必须构建通过；里程碑内至少执行一次全量测试 |

### 8.3 上下文与协作约定（AGENT.md）

- 每次新需求：**先出需求文档与技术文档 → 用户评审 → 再开发**，不得跳过评审直接改代码；
- 核心需求与技术约束固化在 AGENT.md，供后续会话快速恢复上下文；
- 会话上下文使用超过 70% 时主动压缩：把已完成工作、当前进度、待办与关键决策写入 AGENT.md 与开发说明文档，再以摘要继续；
- 开发过程中的临时文件（探针工程、测试夹具）放在系统临时目录或构建目录，工作结束后清理，工作区只保留源码、文档与脚本。
