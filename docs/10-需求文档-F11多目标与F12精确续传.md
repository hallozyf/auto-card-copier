## 1. 背景与目标

| 编号 | 目标 | 可量化判定 |
|------|------|-----------|
| G1 | 重要拍摄可一次写入两块盘（例如 NAS + 移动硬盘），避免单点故障 | 一次任务产出于两个目标目录，且**各自独立校验通过** |
| G2 | 拷卡中断（断电、拔卡、强制退出）后可**原地继续**，不必从头再来 | 续传时只拷贝未完成的文件，已完成文件不重复拷贝、不重复校验 |

## 2. 功能需求

### F11 多目标备份

#### F11-A · 副目标配置【P1】
- **功能描述**：设置中除“素材目标根目录”外，可再填写“副目标根目录”。
- **目的**：让双备份成为一次配置、长期生效的能力，而不是每次手动再复制一遍。
- **效果**：
  1. 留空 = 只写主目标（与旧版本行为完全一致）；
  2. 填写后，每次“开始拷贝”都会写两个目标；
  3. 副目标与主目标填成同一目录时直接拒绝并说明原因；
  4. 副目标当前不可用（移动硬盘未插、网络盘断开）时，只写主目标并在日志中记录警告。
- **验收要点**：三种配置（留空 / 有效 / 与主目标相同）分别表现正确。

#### F11-B · 独立计划与独立校验【P1】
- **功能描述**：每个目标各自生成拷贝计划，拷贝完成后分别校验。
- **目的**：防止“主目标校验通过”掩盖“副目标写入失败”，避免双备份形同虚设。
- **效果**：
  1. 两个目标的项目相对路径一致（便于人工对照），物理位置各自独立；
  2. 每个目标产出自己的校验清单与项目元数据；
  3. 校验失败只影响该目标，另一个目标的结果不受牵连。
- **验收要点**：人为破坏副目标中的一个文件，只有副目标被判定失败。

#### F11-C · 结果判定与呈现【P1】
- **功能描述**：汇总多目标执行结果，界面明确区分三种结局。
- **目的**：让用户一眼知道“备份到底成不成”，而不是靠猜。
- **效果**：
  1. 全部成功 → “全部 N 个目标均已完成并校验通过”；
  2. 部分成功 → 明确列出哪个目标失败与失败原因（未连接、空间不足等）；
  3. 全部失败 → 明确提示；
  4. 进度区显示目标序号，例如第一块盘显示 1/2、第二块显示 2/2。
- **验收要点**：三种结局都能复现且文案正确。

#### F11-D · 执行顺序与性能【P1】
- **功能描述**：两个目标串行写入（先主后备）。
- **目的**：两个目标常位于同一物理盘或同一条网络链路上，并行会互相抢磁头与带宽，反而更慢。
- **效果**：总耗时接近“分别复制两次”之和，不发生目标间争抢导致的明显降速。
- **验收要点**：双目标任务平均速度不低于单目标任务的 70%。

#### F11-E · 安全联动【P0】
- **功能描述**：多目标中任一目标失败时，不解锁格式化。
- **目的**：避免“副目标没写完就格式化卡片”，导致实际只有一份备份。
- **效果**：只有全部目标成功且覆盖率检查通过，格式化按钮才可用。
- **验收要点**：副目标掉线场景下，格式化按钮保持禁用并给出原因。

### F12 精确断点续传

#### F12-A · 任务计划落盘【P1】
- **功能描述**：任务开始时把每个目标、每个文件的源路径、目标路径、大小、时间、类型与状态写入计划文件。
- **目的**：让“进度”成为可恢复的持久状态，而不是只存在于内存中。
- **效果**：
  1. 计划文件位于数据目录的 tasks 子目录，文件名由任务号构成，内容为缩进 JSON，可直接阅读；
  2. 每个文件完成后状态记为 Done，失败记为 Failed；
  3. 任务全部成功后自动删除计划文件，避免下次误提示。
- **验收要点**：中断后计划文件中的 Done 与 Pending 数量与实际落盘文件一致。

#### F12-B · 启动检测与提示【P1】
- **功能描述**：程序启动时检查上次是否有被中断的任务及其计划文件，并给出明确提示。
- **目的**：让用户知道“上次没拷完、还剩多少”，而不是自己回忆。
- **效果**：提示形如“上次任务未完成：还剩 N 个文件未拷贝”；源卡未插回时提示“源卡片未连接”。
- **验收要点**：正常结束的任务不再提示；被中断的任务必提示且数量正确。

#### F12-C · 继续上次任务【P1】
- **功能描述**：点击“继续上次任务”直接补拷未完成文件。
- **目的**：省掉重新扫描整张卡的时间，也避免重复校验已完成文件。
- **效果**：
  1. 不需要重新扫描卡片；
  2. 已完成文件被跳过，本轮只拷贝剩余文件；
  3. 补拷完成后重新校验并做覆盖率检查；
  4. 全部通过后删除计划文件并解锁格式化。
- **验收要点**：模拟“完成 2 个共 5 个”后继续，本轮只拷贝 3 个，最终目标目录 5 个文件且字节一致。

#### F12-D · 数据保真【P0】
- **功能描述**：续传还原的计划必须与原始计划一致。
- **目的**：续传不能引入“文件放错位置”或“时间戳被改动”这类隐性错误。
- **效果**：目标路径、媒体类型、源文件最后写入时间与原始计划完全一致。
- **验收要点**：还原后逐项比对路径、类型、时间戳全部相同。

#### F12-E · 失败重试与不可续传的处理【P1】
- **功能描述**：单文件失败自动重试；计划丢失或损坏时给出明确说明。
- **目的**：避免用户误以为“没提示就是没问题”。
- **效果**：单文件失败重试 3 次（间隔 1 秒、3 秒、9 秒）；计划文件损坏或源卡不在时，明确提示无法继续，并可退回“重新扫描后拷贝”。
- **验收要点**：人为损坏计划文件后，界面给出可理解提示且程序不崩溃。

## 3. 非功能需求

| 类别 | 要求 |
|------|------|
| 兼容性 | 未配置副目标时，行为与 v0.1.x 完全一致，不改变既有使用习惯 |
| 数据兼容 | 旧版配置文件缺少新字段时自动补默认值，不报错 |
| 可靠性 | 计划文件采用“临时文件 + 改名”的原子写入，断电不产生半个 JSON |
| 可维护性 | 多目标与续传逻辑放在 Core 层，可被自动化测试直接覆盖 |
| 性能 | 计划文件只在任务边界写入；单文件完成仅更新内存状态，不产生额外磁盘 I/O |

## 4. 界面需求

| 位置 | 变化 |
|------|------|
| 设置页 | 新增“副目标根目录（可选，用于双备份）”输入框 |
| 卡片页 | 新增“继续上次任务”按钮；续传提示显示在格式化区域上方 |
| 进度区 | 多目标时显示目标序号 |
| 结果区 | 逐条列出每个目标的结果与失败原因 |

## 5. 数据规范

| 文件 | 位置 | 说明 |
|------|------|------|
| settings.json | 数据目录 | 新增副目标根目录字段 |
| 任务计划文件 | 数据目录/tasks | 任务号、项目号、源卡根、拍摄信息、卡指纹、各目标及其文件状态 |
| 校验清单与项目元数据 | 每个目标的项目目录 | 每个目标各写一份 |

## 6. 验收标准

| 编号 | 验收项 | 判定方式 |
|------|--------|----------|
| A1 | 配置副目标后一次任务写入两个目标 | 实测两个目录内容一致 |
| A2 | 副目标与主目标相同被拒绝 | 界面提示且不执行 |
| A3 | 副目标离线时主目标成功 | 结果区显示部分成功 |
| A4 | 任一目标失败时不解锁格式化 | 格式化按钮禁用 |
| A5 | 中断后可继续上次任务且只补拷未完成文件 | 实测拷贝数量 |
| A6 | 续传还原的计划与原始计划一致 | 路径、类型、时间戳逐项比对 |
| A7 | 未配置副目标时行为与旧版一致 | 回归历史 72 条用例 |
| A8 | 全部用例通过 | 测试脚本退出码为 0 |

## 7. 本期不做

- 三个及以上目标（当前支持 1 至 2 个）；
- 目标间并行写入（串行更稳，且多数场景两块盘共享链路）；
- 续传时自动清理异常断电遗留的临时文件（会被后续拷贝覆盖，暂不主动清理）；
- 支持“换另一张卡继续”（源卡指纹不一致时不做处理）。

## 8. 风险与依赖

| 编号 | 风险 | 应对 |
|------|------|------|
| R1 | 双目标写入时间翻倍 | 副目标可选；串行执行避免争抢；界面显示每目标进度 |
| R2 | 用户误填副目标为系统盘 | 目标必须是已存在且可写的目录；格式化护栏仍然只针对卡片 |
| R3 | 计划文件长期堆积 | 任务成功后自动删除；失败或中断的任务保留供续传 |
| R4 | 续传时源卡内容已变化 | 计划记录源文件路径与长度；续传后仍会完整校验 |
