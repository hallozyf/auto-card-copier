# 技术文档 · 多日素材自动分组（按拍摄日期生成多个项目）

> **文档版本**：v1.0 ｜ **状态**：待评审（**未获批准前不写代码**）｜ **日期**：2026-10-12
> **配套需求文档**：docs/14-需求文档-多日素材自动分组.md ｜ **基线版本**：v0.3.0
> **硬性约束（沿用已有原则）**：界面线程不做任何耗时 I/O；跨网络路径访问必须带超时；危险操作默认拒绝

---

## 1. 涉及技术

| 领域 | 技术 |
|------|------|
| 照片时间 | EXIF 解析：IFD0 的 0x0132（DateTime）、Exif SubIFD 的 0x9003（DateTimeOriginal）与 0x9004（DateTimeDigitized），格式 yyyy:MM:dd HH:mm:ss |
| 视频时间 | ISO BMFF 盒解析：moov → mvhd 的 creation_time（自 1904-01-01 UTC 起的秒数）；AVCHD/MTS 等读不到时回退文件时间 |
| 分组算法 | 按“日界偏移后的日期”分桶，O(n) 单遍；组内维护时间范围与分类计数 |
| 界面 | WPF 分组表格（ListView 虚拟化 + 可编辑列），多项目进度展示 |
| 持久化 | 任务计划文件结构升级（一个目标 → 多个分组 → 多个文件） |
| 性能 | 仅读文件头（照片 64 KB、视频 256 KB），有界并发（默认 4），进度上报与取消 |

## 2. 实现路径

### 2.1 拍摄时间提取（F13-A）

```
MediaTimestampReader.TryRead(path, kind)
  ├─ 照片：解析 EXIF
  │     ├─ 定位 TIFF 头（复用现有 ExifReader 的定位逻辑）
  │     ├─ 读 IFD0 → 找到 Exif SubIFD 偏移（0x8769）
  │     ├─ 在 SubIFD 中取 0x9003（DateTimeOriginal）→ 0x9004 → 0x0132
  │     └─ 解析 "yyyy:MM:dd HH:mm:ss"（无时区，按相机本地时间处理，不做换算）
  ├─ 视频：解析 MP4/MOV 容器
  │     ├─ 顺序读取 ftyp/moov/mvhd（必要时按盒长度跳过 mdat）
  │     ├─ 取 creation_time（1904 纪元秒）→ 转 UTC → 转本地时间
  │     └─ 失败或时间明显异常（如 1970/1904 年）→ 视为不可用
  └─ 回退：文件最后写入时间（LastWriteTime）
  返回：ShootTime + 来源枚举（ExifOriginal / ExifDigitized / ExifCommon / Container / FileTime / Unknown）
```

要点：
1. 复用现有最小 EXIF 解析器，扩展为可读取 SubIFD（当前只读 Make/Model）；
2. 视频解析只读容器头，遇到 mdat 直接按长度跳过，不读数据体；
3. 异常时间（小于 1990 年、大于当前时间 +1 天）不采信，直接回退；
4. 提取过程有界并发，且每一步都可取消。

### 2.2 分组（F13-B）

```
MediaDayGrouper.Group(files, dayBoundaryOffset)
  key = (shootTime - dayBoundaryOffset).Date      // 日界默认 00:00，可配置（例如 04:00）
  对每个文件：累加到对应 key 的分组（计数、字节、最早/最晚时间）
  未知时间 → 单独一组（key = null）
  输出：按日期升序的分组列表
```

### 2.3 项目信息填写（F13-C）

- 每个分组生成一个 ProjectContext：ShootDate = 分组日期，ShootType/Location 取“全局默认 + 行内覆盖”；
- 项目名默认用现有命名模板的“最后一段”生成（例如 2026-10-03_人像写真_百旺公园），用户可改写；
- 目标路径 = 目标根 + 模板展开（日期取分组日期）；
- 校验：空名、非法字符（自动清洗并提示）、同批分组内目录重复（建议改成 序号 提示用户确认）。

### 2.4 多项目拷贝（F13-D）

```
对每个分组（项目）：
    生成该项目自己的 CopyPlan（文件清单为该分组的素材）
    对每个目标（主/副）：探测 → 预检 → 拷贝 → 校验
    写入该项目的 _manifest.json / _project.json / _copy.log
汇总：成功项目数、失败项目数、逐项目结果
覆盖率检查：以全部分组的源文件为口径；全部覆盖且全部项目成功才解锁格式化
```

失败处理：单个项目失败（或某目标的某项目失败）**不中断**其它项目；最终汇总里逐条列出。

## 3. 数据结构

### 3.1 扫描结果扩展

| 字段 | 说明 |
|------|------|
| ScannedFile.ShootTime | 拍摄时间（本地时间；未知为 null） |
| ScannedFile.ShootTimeSource | 来源：ExifOriginal / ExifDigitized / ExifCommon / Container / FileTime / Unknown |
| ScanResult.Groups | 日期分组集合：日期、时间范围、照片/视频/其它计数、字节数、文件索引 |
| ScanResult.UnknownTimeCount | 无法确定时间的文件数 |

### 3.2 任务计划文件（结构版本 2）

```
taskPlan
├─ schemaVersion = 2
├─ taskId / projectId / sourceRoot / 卡指纹 / 拍摄信息（保留）
└─ targets[]
     ├─ root / isPrimary
     └─ projects[]                      ← 新增一层（多日分组）
          ├─ name / relativePath / shootDate
          └─ items[]  { source, target, length, lastWriteUtc, kind, state, error }
```

兼容策略：读取时按 schemaVersion 分支；版本 1（单项目）自动升级为“一个 target 下只有一个 project”。

## 4. 关键取舍与风险控制

| 决策 | 原因 |
|------|------|
| 照片时间不做时区换算 | EXIF 没有时区，相机写的是**本地时间**；强行换算会造成日期偏移 |
| 视频容器时间按 UTC 解析后再转本地，并标注来源 | 遵循 MP4 规范；个别厂商写本地时间时，界面会显示来源与时间范围，便于你发现异常 |
| 异常时间不采信 | 宁可标“未知日期”，也不要生成一个错误的项目日期 |
| 未知时间单独成组 | 不静默合并进别的日期，避免素材被塞进错误项目 |
| 单日卡不显示分组表格 | 保持最常用的场景零新增操作 |
| 分组是“拷贝前的计划”，不是“拷贝后的整理” | 目录名一次到位，省掉拷完再改名/移动 |
| 计划文件结构升级为版本 2 | 续传必须能精确表达“哪个目标、哪个项目、哪个文件” |
| 只读文件头 | 20,000 个文件时，整读不可接受；容器解析遇 mdat 直接跳过 |

| TU-G-07 | 日界设为 04:00 的凌晨素材 | 归入前一天 |
| TU-G-08 | 未知时间素材 | 单独成组且计数正确 |
| TU-G-09 | 跨午夜视频（23:50 开始） | 按开始时间归组 |

## 6. 对现有行为的影响

| 影响面 | 说明 |
|--------|------|
| 扫描耗时 | 每个媒体文件多读一次文件头；400 文件量级预计增加 1 至 3 秒（取决于卡速） |
| 界面 | 多日时卡片页新增分组表格；单日时布局不变 |
| 拷贝时长 | 项目数不影响总字节数，但由于逐项目顺序执行，目录切换与清单写入略有增加 |
| 计划文件 | 结构升级；旧文件可读（自动升级） |
| 格式化护栏 | 判据由“本次任务全覆盖”扩展为“全部项目成功 + 全覆盖”，更严格（不放松） |
