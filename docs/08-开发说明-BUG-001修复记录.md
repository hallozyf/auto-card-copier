# 开发说明 · BUG-001 修复记录（视频文件未被扫描）

> 对应报告：docs/07-排故报告-BUG-001-视频未被扫描.md ｜ **修复版本**：v0.1.1
> **修复日期**：2026-03-10 ｜ **用户确认**：用户卡上视频位于 D:\PRIVATE\M4ROOT\CLIP，同意采用方案 B + C

## 1. 修复概述

| 项目 | 内容 |
|------|------|
| 缺陷 | 只扫描"第一个特征目录"，导致照片在 DCIM、视频在 PRIVATE / AVCHD / CONTENTS 时整段漏扫 |
| 根因 | CardDetector 只记录第一个素材目录 + MediaScanner"命中特征目录就不再扫描其它目录" |
| 风险 | 漏拷的视频不会进入校验范围，校验却显示通过，进而解锁格式化 → 不可逆数据丢失 |
| 修复方案 | 方案 B（结构化修复：全部素材根 + 卡根扫描 + 目录与扩展名补齐）+ 方案 C（格式化覆盖率兜底） |
| 验证 | 72 个自动化用例全部通过（原 64 + 新增 8 条回归），Release 构建 0 警告 0 错误 |

## 3. 实现方式

### 3.1 扫描范围（核心修复）

修复前：

```
CardDetector：mediaFolders[0] → MediaRootPath（DCIM）
      ↓
界面：Scan( MediaRootPath )
      ↓
MediaScanner：给定目录下若有特征目录，只扫描这些特征目录
      → PRIVATE / AVCHD 永远不在范围内
```

修复后：

```
CardDetector：记录全部命中的特征目录（MediaRootPaths），并提供 ScanRootPath = 卡根
      ↓
界面：Scan( ScanRootPath )     ← 始终从卡根开始
      ↓
MediaScanner.ResolveScanRoots(卡根, 设置)：
      ① 全部特征目录（DCIM / M4ROOT / AVCHD / XDROOT / PRIVATE / CONTENTS / MP_ROOT / VIDEO / MOVIE / CLIP / BMD …）
      ② 若 ScanWholeCardRoot（默认开启）：卡根下其余非忽略目录
      ③ 一个特征目录都没有时才直接扫描卡根
```

这样无论相机把视频放在标准目录还是自建目录，都不会再被静默跳过。

### 3.2 机制性兜底（比"修好这一处"更重要）

即使将来又出现"范围判断错误"，也不应该演变成数据丢失，因此新增两道保护：

1. 拷贝并校验完成后，CoverageChecker 重新枚举卡片，统计"卡上存在、但不在本次拷贝计划里"的素材文件；
2. 只要该类文件数量大于 0：
   - 界面结果显示 "⚠️ 卡上还有 N 个素材（共 M 个）未被本次拷贝覆盖" 并列出示例；
   - **不解锁格式化**（DiskSafetyInspector 第 6 条规则），提示"请先完成这些素材的拷贝"；
   - 该规则被抽成纯函数 CheckCoverageRule，可被单元测试直接覆盖。

### 3.3 诊断留痕

- 扫描时日志写入"扫描范围（N 个顶层目录）：…"；
- 卡片页"素材统计"下方新增"扫描范围"与覆盖率文本，用户可一眼确认软件到底扫了哪些目录。

## 4. 行为变化（需要知晓）

| 变化 | 说明 |
|------|------|
| 扫描范围变大 | 卡根下的其它目录（例如 MISC、自建目录）也会被扫描，"其他文件"统计数量可能比之前多，这是预期行为（不再静默跳过） |
| 新增设置项 | "扫描卡根下的所有目录"默认**开启**；关闭后仍会扫描全部特征目录，只是不再扫描自建目录 |
| 格式化解锁条件 | 在"拷贝 + 校验通过"之外，新增"卡上素材已全部覆盖"这一必要条件 |
| 清空卡片 | 由"只清空第一个素材目录"改为覆盖全部素材根（照片与视频可能分处不同目录） |
| 新增设置字段 | settings.json 新增 scanWholeCardRoot；旧配置文件加载时自动补默认值 true，无需人工处理 |

## 6. 遗留问题

| 编号 | 问题 | 说明 |
|------|------|------|
| R1 | 需用户真机复测 | 请用你的卡（D:\PRIVATE\M4ROOT\CLIP）重新插卡扫描，确认"视频"数量与资源管理器一致 |
| R2 | 覆盖率检查按扩展名识别媒体 | 若相机产生非常规扩展名的视频，覆盖率检查不会把它算作"素材"；后续可在设置中增加"自定义扩展名" |
| R3 | 扫描范围扩大带来额外枚举 | 仅遍历元数据，实测影响很小；若卡根下有超大无关目录，可关闭"扫描卡根下的所有目录" |
| R4 | 格式化护栏第 6 条的端到端验证 | 受开发环境限制（没有 USB 卡），该规则以纯函数单元测试 + 代码审查验证，端到端需真机确认 |

## 7. 经验与提醒

1. **"取第一个命中项"是扫描类逻辑的高危写法**：应当取"全集"，再由明确的规则决定取舍；
2. **危险操作的兜底不能只依赖调用方正确**：调用方一个参数传错就可能造成不可逆后果，护栏必须放在领域层并覆盖拒绝路径；
3. **缺陷修复要带回归用例**：本次新增 8 条用例固定在"BUG-001 回归"分组，任何人改动扫描范围都必须让它们保持通过；
4. **统计口径变化要在文档中显式说明**：扫描范围扩大后"其他文件"数量变化，属于预期行为，必须写清楚以免被当成新 Bug。
