## 1. 项目概览

### 1.1 一句话定位

给摄影师用的 Windows 桌面软件：**插入存储卡 → 自动识别与扫描 → 按拍摄日期分组建项目 → 并行拷贝到文件服务器 → 完整性校验 → 生成自描述清单 → 可选安全格式化**。

三条不可偏离的产品诉求（来自 `AGENT.md` 第 2 章）：

1. 拷卡流程自动化，不再手动建目录、手动复制、手动格式化；
2. 素材项目化管理，每个项目带拍摄时间、地点、拍摄类型；
3. 轻量化、使用 Windows 原生组件、界面美观。

### 1.2 核心业务流程

```
插入存储卡
   │
   ▼
[F01] CardDetector 识别卡片（多重判定 + 指纹）
   │
   ▼
[F02] MediaScanner 只读扫描（分类统计 / 时间范围 / 机型 / 拍摄时间）
   │
   ▼
[F13-B] MediaDayGrouper 按自然日分组（单日卡不显示分组表）
   │
   ▼
[F03] NameTemplateEngine 生成项目目录名 + CopyPlanBuilder 生成计划
   │
   ▼
[F04] CopyEngine 并行拷贝（.acctmp 临时文件 + 长度校验 + 原子改名）
   │
   ▼
[F05] VerifyService 五档校验（默认 大小 + 抽样哈希）
   │
   ▼
[F06/F07] 写 _manifest.json / _project.json / _copy.log + 本地项目库
   │
   ▼
[F10] 覆盖率检查通过且校验通过 → 解锁格式化（六道护栏）
```

## 2. 技术栈与工程约束

### 2.1 技术选型

| 层面 | 选择 | 理由 |
|------|------|------|
| 语言 / 框架 | C# 8.0 + WPF + .NET Framework 4.8 | Win10 1809+/Win11 自带运行时，绿色版零安装 |
| 工程格式 | 传统 csproj（非 SDK 风格） | 开发机无 .NET SDK，只有 MSBuild |
| UI 模式 | 自研极简 MVVM（`ViewModelBase` / `RelayCommand` / `AsyncRelayCommand`） | 不引入 MVVM 框架，保持轻量 |
| 序列化 | `DataContractJsonSerializer` + `SimpleJson.Pretty` | 系统自带，输出人类可读 JSON |
| 数据存储 | JSON 文件（设置、项目库、历史、清单、计划） | 可手工查看与修复，可随 NAS 迁移 |
| 测试 | 自研控制台运行器 + 断言库 | 无 NuGet、无测试框架依赖，退出码即结果 |
| 图标 | Segoe Fluent Icons / Segoe MDL2 Assets 字体字形 | 不打包图片资源 |
| 系统集成 | Win32 P/Invoke（卷信息、设备消息）+ WMI（物理盘）+ `format.com` | 全部为 Windows 原生能力 |

### 2.2 关键编译属性（`build/Common.props`）

| 属性 | 值 | 作用 |
|------|----|------|
| `TargetFrameworkVersion` | `v4.8` | 目标框架 |
| `PlatformTarget` | `x64` | 与系统参考程序集架构一致，消除 MSB3270 |
| `LangVersion` | `8.0` | 语言版本 |
| `Nullable` | `disable` | 未启用可空引用类型 |
| `FrameworkPathOverride` | `C:\Windows\Microsoft.NET\Framework64\v4.0.30319` | 无 Targeting Pack 时提供参考程序集（若安装正式 SDK 可删除） |
| `OutputPath` | `build\out\$(Configuration)\` | 三个工程统一产物目录 |
| `AssemblyVersion` / `Version` | `0.1.0.0` / `0.1.0` | 与 CHANGELOG 未同步 |

### 2.3 硬性工程约束（写在 AGENT.md 与 docs/02，代码中普遍遵守）

1. **模块化**：单个 `.cs` 文件原则上不超过约 400 行（实际有 5 个文件超出，见 14.1 D11）；
2. **UI 与 I/O 分离**：界面线程不做耗时 I/O；所有目标探测必须带超时（BUG-002 的直接教训）；
3. **零第三方依赖**：需要 CRC32、JSON 美化、MVVM 基础设施时自行实现；
4. **默认拒绝**：格式化等不可逆操作先判拒绝路径，再判允许路径；
5. **失败必留痕**：`catch` 必须写日志并转换为结构化结果（`OperationResult`），禁止空 `catch` 吞异常（少数"日志写入失败"场景例外，且有注释说明）；
6. **临时文件不落地**：测试夹具放系统临时目录，构建产物放 `build/out`。

### 2.4 本机环境注意事项

- Windows PowerShell 5.1：`.ps1` 必须保存为 **UTF-8 带 BOM**，否则中文注释会按 ANSI 解析导致脚本失败；
- `.cmd` 包装脚本内只写英文注释（cmd 按 ANSI 解析）；
- 构建脚本内部使用 `-ExecutionPolicy Bypass`，避免执行策略拦截。

## 3. 总体架构

### 3.1 分层与依赖方向

```
┌────────────────────────────────────────────────────────────────────┐
│ 表示层：AutoCardCopier.App                                         │
│ App / MainWindow / Views（5 个页面）/ ViewModels / Themes / Tray    │
│ 职责：绑定、命令、状态展示、主题切换、托盘；不含业务规则            │
└───────────────────────────┬────────────────────────────────────────┘
                            │ 单向 ProjectReference
┌───────────────────────────▼────────────────────────────────────────┐
│ 应用编排：AppServices（手写组合根，无第三方 DI 容器）               │
│ 初始化顺序：设置探针 → 数据目录 → 日志 → 设置 → 领域服务 → 页面 VM │
└───────────────────────────┬────────────────────────────────────────┘
┌───────────────────────────▼────────────────────────────────────────┐
│ 领域服务层：AutoCardCopier.Core                                    │
│ Devices │ Scanning │ Copying │ Projects │ History │ Formatting      │
│ 职责：识别、扫描、规划、拷贝、校验、项目库、历史、格式化            │
└───────────────────────────┬────────────────────────────────────────┘
┌───────────────────────────▼────────────────────────────────────────┐
│ 基础设施：Infrastructure / Logging / Settings / Interop             │
│ JSON、路径、日志、配置、Win32、结果模型、事件总线                    │
└────────────────────────────────────────────────────────────────────┘

AutoCardCopier.Tests ──引用──► Core（不引用 App，保证领域逻辑可脱离界面测试）
```

依赖规则：

1. Core **不引用任何 WPF 类型**（无 `PresentationFramework` 等），因此可被控制台测试直接调用；
2. App 可以引用 Core；Core 不得反向引用 App；
3. Tests 只引用 Core；
4. App 内页面只通过 `AppServices` 访问领域服务，不直接 new 服务。

### 3.2 组合根与生命周期（`App/AppServices.cs`）

`AppServices.Create()` 的初始化顺序经过刻意设计：

```
1. 用默认数据目录（%APPDATA%\AutoCardCopier）读取一次设置，仅用于探明 dataDirectory
2. AppPaths.ResolveDataDirectory：设置指定目录 → %APPDATA% → 程序目录\data → 系统临时目录
3. 创建 FileLogger（logs/app-*.log，含 Debug 级）
4. 正式加载 SettingsStore（损坏自愈）→ Normalize → 记录启动日志 → 清理过期日志
5. 组装领域服务：
   MediaScanner / CardDetector(3s 轮询) / CopyPlanBuilder / CopyEngine /
   ManifestWriter / BackupCoordinator / TaskPlanStore / PresetsStore /
   ProjectLibrary / TaskHistoryStore
```

`App.OnStartup` 负责创建 `AppServices`、应用主题、显示 `MainWindow`；`App.OnExit` 调用 `Shutdown()` 依次释放托盘、卡片检测器、日志。

### 3.3 线程模型

这是本项目最关键的结构约束，直接对应 BUG-002 的教训（`docs/12`）。

```
UI 线程（WPF Dispatcher）
  │  命令处理与属性更新；await 之后自动回到 UI 上下文
  ├─ Backup.BuildPlansAsync
  │     └─ TargetProbe.CheckAsync
  │           └─ 专用后台线程（IsBackground）+ Task.WhenAny(结果, 3s 超时)
  ├─ Backup.RunAsync
  │     ├─ projectGate：项目级并行度（ParallelProjects，1–4）
  │     └─ fileGate：文件级共享闸门（MaxParallelism，1–8，所有单元共用）
  │           └─ Task.Run → CopyEngine.CopyWithTempFile（逐文件）
  ├─ VerifyService：每个执行单元内 Task.Run，单元内顺序校验
  └─ CoverageChecker：Task.Run，整卡复查
```

| 阶段 | 执行位置 | 说明 |
|------|----------|------|
| `ResolveTargets` | 任意线程 | 纯字符串逻辑，不访问文件系统 |
| `TargetProbe.CheckAsync` | 专用后台线程 + 超时 | 目录存在、可写、剩余空间；超时立即返回"目标不可用" |
| `ResolveConflictDirectory` | 后台上下文 | 唯一会访问目标目录的规划步骤 |
| `CopyPlanBuilder.Build/BuildForFiles` | 任意线程 | 纯内存计算，不调用 `File.Exists` / `Directory.Exists` |
| 逐文件"是否跳过" | 拷贝工作线程 | 由 `CopyEngine.ShouldSkipExisting` 判断 |
| 清单、历史、计划文件写入 | 后台或调用线程 | 不放在 UI 线程做长时间 I/O |

> 设计红线：**跨网络路径的任何调用都不能出现在 UI 线程；所有目标探测必须带超时。** 修改 `BackupCoordinator` 或 `CopyPlanBuilder` 时必须保持这条。

### 3.4 结果与异常模型

- 可能失败的操作返回 `OperationResult` / `OperationResult<T>`（`Success`、`Message`、`Error`、`Value`），调用方用 `Success` 分支，不依赖异常控制流程；
- 领域层内部捕获异常后写 `ILog`（`FileLogger` 或 `NullLog`），再转换为失败结果；
- UI 层用 `StatusText` / `ResultSummary` / `Failures` 集合向用户展示，不静默失败；
- 全局兜底：`App.DispatcherUnhandledException` 与 `AppDomain.UnhandledException` 都写日志并提示，避免"程序直接消失"。

## 5. 解决方案与工程

### 5.1 工程清单

| 工程 | 类型 | 输出 | 主要引用 | 说明 |
|------|------|------|----------|------|
| `AutoCardCopier.Core` | Library | `AutoCardCopier.Core.dll` | System、System.Core、System.Runtime.Serialization、System.Xml、**System.Management** | 领域逻辑；WMI 仅用于物理盘判定 |

## 6. Core 模块详解

> 约定：下表"主要类型"只列对外承担职责的类型；每个类型一个文件（`AssemblyInfo.cs` 除外）。

### 6.1 Infrastructure（8 个文件）

| 类型 | 文件 | 职责 |
|------|------|------|
| `OperationResult` / `OperationResult<T>` | `Result.cs` | 统一成功/失败结果，携带中文消息与异常 |
| `JsonStore` | `JsonStore.cs` | DataContract JSON 序列化 + 缩进美化 + **临时文件原子写** + 长路径读取 |
| `SimpleJson` | `SimpleJson.cs` | 紧凑 JSON 美化；JSONL 单行输出 |
| `PathUtil` | `PathUtil.cs` | 长路径前缀（`\\?\`、`\\?\UNC\`）、UNC 判断、命名清洗、唯一命名、子路径判断 |
| `Humanize` | `Humanize.cs` | 字节、速度、时长、数量的中文友好格式 |
| `TimeUtil` | `TimeUtil.cs` | ISO 8601 读写、高精度 UTC、显示格式、解析容错 |
| `EventBus` | `EventBus.cs` | 进程内同步发布/订阅，单个订阅者异常隔离（当前未被业务代码使用，见 14.1 D8） |
| `AppPaths` | `AppPaths.cs` | 数据目录解析（设置 → %APPDATA% → 程序目录\data → 临时目录）及各子路径 |

关键设计：**所有 JSON 写入都走 `WriteAllTextAtomic`**（`.tmp` → 删除旧文件 → 改名），避免断电/崩溃留下半截配置或清单。

### 6.2 Logging（3 个文件）

| 类型 | 职责 |
|------|------|
| `ILog` / `LogLevel` / `NullLog` | 日志抽象；`NullLog` 用于测试与早期初始化 |
| `FileLogger` | 按天滚动（`app-yyyy-MM-dd.log`）、单文件 10 MB 后加序号、保留天数清理；写日志失败静默 |
| `TaskJournal` | 每任务一个 `.jsonl`，一行一事件；当前未被拷贝流程实例化（见 14.1 D8） |

### 6.3 Settings（2 个文件）

| 类型 | 职责 |
|------|------|
| `AppSettings` | 全部配置字段与默认值；`Normalize` 把越界值夹回合法范围；`[DataContract]` 决定 JSON 字段名 |
| `SettingsStore` | 加载/保存；文件损坏时改名为 `settings.json.bad` 并回退默认值；原子写入 |

### 6.4 Interop（1 个文件）

`NativeMethods` 只声明实际用到的 Win32 API：

- 常量：`WM_DEVICECHANGE`、`DBT_DEVICEARRIVAL`、`DBT_DEVICEREMOVECOMPLETE`、`DBT_DEVTYP_VOLUME`；
- `GetVolumeInformation`：卷标、卷序列号、文件系统；
- `GetDiskFreeSpaceEx`：总容量、可用容量；
- 封装为 `TryGetVolumeInformation` / `TryGetDiskFreeSpace`，失败返回 `false` 而不是抛异常。

> 注意：代码中**没有** `CreateFile` / `DeviceIoControl` / `FSCTL_LOCK_VOLUME`，与 docs/02 对格式化前"锁卷并卸载"的描述不一致（见 14.1 D10）。

### 6.5 Devices（4 个文件）

| 类型 | 职责 |
|------|------|
| `VolumeInfo` / `VolumeApi` | 读取单个卷信息；枚举所有已就绪卷（跳过光驱、无根目录、未就绪） |
| `CardVolume` | 一张被判定为"相机卡"的卷：盘符、卷标、文件系统、容量、指纹、全部素材根、判定原因 |
| `CardIdentity` | 卡片指纹：`{序列号:X8}|{卷标}|{总容量}`；换盘符仍识别为同一张卡 |
| `CardDetector` | 事件 + 3 秒轮询 + 800 ms 防抖；多重判定；变化时触发 `CardsChanged` |

判定顺序（`CardDetector.BuildCard`）：

```
排除系统盘
  → 卡根下是否存在 13 个特征目录之一（DCIM/M4ROOT/AVCHD/XDROOT/PRIVATE/BMD/CANON/NIKON/CONTENTS/MP_ROOT/VIDEO/MOVIE/CLIP）
  → 卷标是否命中相机卡关键字
  → 是否 Removable 且容量 > 0
  → 都不满足则不是卡片
```

`MediaRootPaths` 保留**全部**特征目录（BUG-001 修复点），`ScanRootPath` 始终为卡根。

### 6.6 Scanning（7 个文件）

| 类型 | 职责 |
|------|------|
| `ScannedFile` / `ScanProgress` / `ScanResult` | 扫描数据模型：文件、进度、分类统计、时间范围、机型、分组、扫描根 |
| `MediaClassifier` | 扩展名分类（照片/视频/其他）、RAW 判定、垃圾文件判定、目标子目录解析（照片/视频/其他，RAW/JPG） |
| `MediaScanner` | 只读递归扫描；决定扫描根；跳过忽略目录、垃圾文件、0 字节文件；统计；提取拍摄时间；分组；最多 20 张照片识别机型；200 ms 节流进度 |
| `ExifReader` | 最小 EXIF 解析：TIFF 头 + IFD0 的 Make/Model，失败返回空 |
| `MediaTimestampReader` | 拍摄时间统一入口：照片 EXIF（Original → Digitized → Common）、视频 mvhd、回退文件时间；异常时间不采信 |
| `MediaDayGrouper` | 按自然日 `ShootTime.Date` 分桶；未知时间单独成组；组内按拍摄时间排序；统计守恒 |
| `CoverageChecker` | 拷贝后重新枚举整卡，计算"未被本次拷贝覆盖"的照片/视频数量，作为格式化护栏第 6 条的依据 |

扫描根解析（BUG-001 的核心修复）：

```
roots = 所有存在的特征目录
      ∪ （ScanWholeCardRoot=true 时）卡根下其它非忽略目录
若 roots 为空 → 直接扫卡根
```

### 6.7 Copying（9 个文件）

| 类型 | 职责 |
|------|------|
| `CopyAction` / `CopyItem` / `CopyPlan` / `PlanPreflight` | 拷贝计划：源、目标、动作、待拷数量/字节、预检结果 |
| `CopyPlanBuilder` | 纯内存生成计划（不访问文件系统）；目录冲突解析（会访问文件系统，须后台调用）；异步预检（TargetProbe + 1.05 空间余量） |
| `CopyEngine` | 并行拷贝；**`.acctmp` + 长度校验 + 原子改名**；保留时间戳；逐文件跳过判断；3 次重试（1/3/9 秒退避）；取消清理；共享闸门 |
| `PauseToken` | 文件边界与块边界的暂停/继续 |
| `HashUtil` | 自研 CRC32（查表）、SHA-256、抽样哈希（首/中/尾各 1 MB，小于 3 MB 退化为全量） |
| `VerifyService` | 五档校验；先比长度再比内容；视频可选跳过哈希；失败清单 |
| `ManifestWriter` | 写 `_manifest.json` / `_project.json` / `_copy.log`；构造 `ProjectMeta`；CSV 导出（静态方法） |
| `TargetProbe` | 目标可用性探测：专用后台线程 + 3 秒超时 + 写探针文件；BUG-002 的关键修复 |
| `BackupCoordinator` | 多项目 × 多目标矩阵：解析目标、探测、生成计划、并行执行、按项目汇总 |

执行单元模型：

```
执行单元 BackupUnit = 项目 ProjectGroupRequest × 目标 Root
  ├─ Probe / Preflight / Plan
  ├─ Copy / Verify
  └─ Succeeded / Message

BackupPlanSet = Units[] + UnavailableTargets[] + Groups[]
BackupResult  = Units[] + Projects[] + AllSucceeded / AnySucceeded / Cancelled + 汇总
```

### 6.8 Projects（4 个文件）

| 类型 | 职责 |
|------|------|
| `ProjectContext` / `NameTemplateEngine` | 命名上下文；模板展开（`yyyy`、`yy`、`mm`、`month`、`dd`、`yyyy-mm-dd`、`hh`、`mm2`、`hhmm`、`type`、`location`、`photographer`、`camera`、`card`、`seq`）；逐段清洗；未识别占位符原样保留 |
| `ProjectMeta` | 项目元数据模型（写入 `_project.json` 与本地项目库）；`NewId` = 时间戳 + 6 位 GUID |
| `Presets` / `PresetsStore` | 拍摄类型（10 个内置）、最近地点（最多 30 个）、默认类型；`presets.json` 读写 |
| `ProjectLibrary` | 一项目一文件；加载/检索/保存/更新（双写本地 + 服务器 `_project.json`）/删除本地记录/从服务器重建（最大递归 4 层，`updatedAt` 较新者胜出） |

> 项目库**不再维护 `index.json`**：启动时直接扫描 `projects/*.json`。这是对 docs/02 §3.3 的有意偏离（docs/06 L4 已记录）；项目数上万时需要重新评估。

### 6.9 History（2 个文件）

| 类型 | 职责 |
|------|------|
| `TaskHistoryStore` | 单文件 `history.json`；按 Id Upsert；最多 2000 条；启动时把残留 `Running` 记录标记为失败并返回给界面提示续传 |
| `TaskPlanStore` | 精确断点续传计划：从 `CopyPlan` 生成、按 `CopyResult` 回写状态、还原成计划、原子保存、读取、删除；文件为 `tasks/{taskId}.plan.json` |

### 6.10 Formatting（2 个文件）

| 类型 | 职责 |
|------|------|
| `DiskSafetyInspector` | 通过 WMI 把盘符映射到物理盘；六道硬护栏；纯函数 `CheckCoverageRule` 便于单测；可枚举物理盘 |
| `CardFormatter` | 调用系统 `format.com`（`/FS /Q /Y /V`，180 秒超时）；结果复核；失败原因翻译；`EraseFiles` 只删文件保留目录结构 |

六道护栏（代码级强制，不可配置）：

1. 不是系统盘；
2. `DriveType` 不是 Network / CDRom / NoRootDirectory；
3. 物理盘不是系统盘所在物理盘；
4. 物理盘 `InterfaceType == USB`；
5. 存在"本次拷贝 + 校验通过"凭证；
6. `uncoveredMediaCount == 0`（卡上素材已全部覆盖）。

界面层还额外要求：当前卡指纹等于最近一次校验通过的卡指纹，且当前无进行中的任务（`CardsViewModel.CanFormatCard`）。

## 9. 数据与文件格式

### 9.1 本地数据目录

默认 `%APPDATA%\AutoCardCopier`；可通过 `settings.json` 的 `dataDirectory` 改为程序目录（便携模式）。若候选目录都不可写，回退到系统临时目录。

```
<数据目录>/
├─ settings.json                 软件设置（损坏时备份为 settings.json.bad 并重建默认值）
├─ history.json                  任务历史（单文件，最多 2000 条，按开始时间倒序读取）
├─ presets.json                  拍摄类型与最近地点
├─ projects/
│  └─ {projectId}.json           一项目一文件（本地项目库）
├─ tasks/
│  └─ {taskId}.plan.json         精确断点续传计划
└─ logs/
   ├─ app-2026-10-19.log         按天滚动；超过 10 MB 变 app-日期.1.log
   └─ tasks/                     预留的任务流水目录（TaskJournal 当前未接线）
```

### 9.2 服务器侧项目目录

```
<目标根>/
└─ 2026/                                  年份段来自命名模板
   └─ 2026-10-03_人像写真_百旺公园/        项目目录（模板最后一段）
      ├─ 照片/
      │  ├─ RAW/                          仅 ByMediaTypeAndFormat 模式
      │  └─ JPG/
      ├─ 视频/
      ├─ 其他/
      ├─ _manifest.json                   机器可读的完整校验清单
      ├─ _project.json                    跨机器可读的项目元数据
      └─ _copy.log                        人类可读的本次任务摘要
```

要点：

- 目标目录是**按媒体类型分类的扁平结构**，不保留卡内 `DCIM/100CANON` 等层级；
- 同一项目内同名文件由 `CopyPlanBuilder.EnsureUniqueTarget` 追加 `_2`、`_3` 后缀；
- 多目标时每个目标各写一份三个附带文件，任意一块盘都能自描述；
- 目录冲突按 `ConflictPolicy`：`AutoRenameDir`（默认，追加序号）或 `Merge`（合并）；代码枚举里还有 `Ask`，但界面只提供前两项。

- 全部成功且覆盖率通过后删除计划文件；文件损坏时视为无计划，保留原文件。

## 11. 关键机制专题

### 11.1 卡片识别与指纹

- **多重判定**：特征目录 → 卷标关键字 → 可移动介质兜底，避免 CFexpress/XQD 被报告为固定磁盘时漏识别；
- **指纹**：`序列号 | 卷标 | 总容量`，换盘符仍是同一张卡；用于 UI 还原选中项、格式化凭证匹配、防重复导入提示；
- **防抖与轮询**：一次插卡可能触发多条消息，800 ms 内只刷新一次；另有 3 秒轮询兜底不发消息的读卡器；
- **只读**：识别阶段只做 `Directory.Exists` 与卷信息读取，不写卡。

### 11.2 扫描范围与覆盖率护栏（BUG-001）

- 早期实现只记录"第一个特征目录"，导致"照片在 DCIM、视频在 PRIVATE/AVCHD"的卡整段漏扫视频；
- 修复后：`MediaRootPaths` 记录全部特征目录，扫描入口统一为卡根，扫描范围 = 全部特征目录 ∪ 卡根其它非忽略目录；
- 兜底：拷贝完成后 `CoverageChecker` 重新枚举整卡，若存在未被本次拷贝覆盖的照片/视频，则禁止解锁格式化；
- 界面显示实际扫描范围与覆盖率文本，便于排查"为什么没扫到"。

### 11.3 原子拷贝与重试

```
写目标目录/{文件名}.acctmp
 → 分块读写（SequentialScan，缓冲可配）
 → Flush(true)
 → 校验写入字节数 == 源长度
 → 校验临时文件长度
 → 删除同名目标（如存在）→ File.Move 临时文件 → 目标名
 → 设置 LastWriteTimeUtc / CreationTimeUtc
失败 → 删除临时文件 → 退避重试（1 s / 3 s / 9 s，共 3 次）→ 仍失败记入失败清单
```

保证：目标目录不会出现半截文件；取消时清理临时文件；单文件失败不影响其他文件。

### 11.4 五档校验

| 档位 | 行为 | 适用 |
|------|------|------|
| `None` | 不校验 | 极速场景，格式化护栏会因"无校验凭证"而拒绝解锁 |
| `SizeOnly` | 只比长度 | 快速确认，允许内容损坏漏检 |
| `SizeAndSample`（默认） | 长度 + 首/中/尾各 1 MB 哈希；小于 3 MB 退化为全量 | 日常拷卡，耗时可控 |
| `Crc32` | 长度 + 全量 CRC32 | 中等强度，自研查表实现 |
| `Sha256` | 长度 + 全量 SHA-256 | 最严格，耗时最长 |

校验在单元内**顺序**执行，避免并行随机读拉低机械盘/网络盘吞吐；视频可通过 `verifyVideo=false` 跳过哈希。

### 11.5 多目标 × 多项目调度

```
项目数 P，目标数 T → 执行单元数 P × T
projectGate = min(4, ParallelProjects)     控制同时执行的项目数
fileGate    = min(8, MaxParallelism)       控制所有单元合计的并发文件数
```

- 所有单元共享同一个 `fileGate`，避免"项目并行 × 文件并行"导致并发乘积；
- 单个单元失败不中断其他单元；最终汇总为全部成功 / 部分成功 / 全部失败；
- 探测失败的目标登记为失败单元，并阻止解锁格式化（不再静默跳过）；
- 执行前复检一次目标可用性，覆盖"生成计划后拔盘/断网"的窗口期。

### 11.6 线程与超时（BUG-002 的教训）

| 问题 | 现状 |
|------|------|
| 目标探测阻塞 UI | `TargetProbe` 专用后台线程 + 3 秒超时，超时即判不可用 |
| 计划阶段逐文件探测网络目标 | 已移除；计划纯内存，跳过判断下沉到拷贝工作线程 |
| 副目标离线被静默跳过 | 改为显式失败 + "部分成功" + 阻止格式化 |
| 网络 I/O 无超时 | 所有目标访问统一走 `TargetProbe` 或拷贝工作线程 |

回归用例 `BG-01` 至 `BG-05` 专门保护这条约束，包括"不可达副目标 + 400 个文件"的复现场景。

### 11.7 格式化安全设计

- 护栏写在 `DiskSafetyInspector`，**不读配置、不可关闭**；
- 先判拒绝路径，再判允许路径；测试优先覆盖拒绝路径；
- 格式化前再检查一次（`CardFormatter` 内部调用 `Inspect`），避免调用方绕过；
- 失败原因翻译：占用、写保护、不支持的文件系统、拒绝访问，各自给出可操作提示；
- 成功后重新读取卷信息复核，并提示可以安全拔卡。

### 14.2 技术债与风险

| 类别 | 风险 | 说明 / 缓解 |
|------|------|-------------|
| 性能 | 项目库全量扫描 | 千级项目可接受；上万项目启动变慢，docs/06 L4 已记录，届时应加索引缓存 |
| 性能 | 覆盖率检查二次遍历整卡 | 拷贝后同步等待，大卡会增加收尾时间；可用"仅比对扫描快照"优化，但会削弱 BUG-001 兜底 |
| 性能 | 拍摄时间提取逐文件读头 | 4 线程有界并发；超大卡可切"快速模式"（只用文件时间） |
| 可靠性 | `format.com` 输出本地化 | 失败原因映射依赖英文关键字；中文系统可能落到通用兜底，提示不够精确 |
| 可靠性 | WMI 依赖 | `System.Management` 服务异常/权限受限时物理盘判定失败，护栏会**安全拒绝**（不会误格式化） |
| 可靠性 | 探测线程可能被底层 I/O 卡住 | 已隔离为后台线程 + 超时返回；线程会短暂驻留（docs/13 R2） |
| 兼容性 | 仅接受 USB 接口 | Thunderbolt CFexpress 读卡器会被拒绝格式化（识别本身不受影响） |
| 兼容性 | 目标目录扁平化 | 不保留卡内目录层级；同名文件加序号；如用户依赖原始层级需评估 |
| 体验 | 托盘图标为系统通用图标 | 无专属图标资源；不影响功能 |
| 体验 | 无安装包/无代码签名 | SmartScreen 可能提示；当前定位绿色版 |
| 维护性 | 文档与代码双份事实 | docs/02 是 v0.1 设计稿，多处已被实现超越；建议把"现状"集中到本文与 AGENT.md |
| 测试 | 缺少真实硬件路径 | 格式化拒绝路径覆盖充分，但成功路径、真实 NAS 性能、拔卡恢复仍需人工验收 |

### 14.3 建议的下一步（按优先级）

1. **统一版本号**（D1），并在 CI/构建脚本中从 CHANGELOG 或单一版本文件注入；
2. **补一条多项目续传用例**（D5），确认计划文件在 3 项目 × 2 目标中断后能正确还原；
3. **重写 README 与 AGENT 的进度/测试数字**（D2/D3），避免误导；
4. **处理无效设置项**（D7）：要么实现，要么从界面移除；
5. **拆分 `CardsViewModel`**（D11），先把"扫描/分组"和"拷贝/续传"拆开；
6. **真机验收**（D12）：真实卡 + NAS + 400 文件以上 + 格式化一次，记录结果到 docs/16 或新开发说明。

## 17. 术语表

| 术语 | 含义 |
|------|------|
| 源 / Source | 存储卡上的素材目录（DCIM、PRIVATE、AVCHD 等） |
| 目标根 / Target Root | 素材存放的服务器根目录（盘符或 UNC） |
| 项目 / Project | 一次拍摄对应的一条元数据 + 一个磁盘目录 |
| 拷贝计划 / Copy Plan | 拷贝前的文件清单：源、目标、大小、动作 |
| 执行单元 / BackupUnit | "项目 × 目标"的组合，独立计划、独立拷贝、独立校验 |
| 校验清单 / Manifest | `_manifest.json`，文件级大小与哈希记录 |
| 覆盖率 / Coverage | 卡上照片+视频是否全部纳入本次拷贝 |
| 卡片指纹 / Fingerprint | 卷序列号 + 卷标 + 总容量，用于识别同一张卡 |
| 原子改名 | 先写 `.acctmp`，长度校验后 `File.Move` 为目标名 |
| 抽样哈希 | 首/中/尾各 1 MB 的 SHA-256 组合，兼顾速度与可靠性 |
| 快速模式 | 拍摄时间直接用文件修改时间，不解析 EXIF/容器 |
| 绿色版 | 免安装，复制目录即可运行，仅依赖系统自带 .NET Framework |
