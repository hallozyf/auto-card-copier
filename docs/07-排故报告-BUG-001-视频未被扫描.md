# 排故报告 · BUG-001：存储卡中的视频文件未被扫描到

> **报告编号**：BUG-001 ｜ **严重级别**：🔴 严重（有数据丢失风险）｜ **状态**：待审批
> **发现方式**：用户实机使用反馈 ｜ **报告日期**：2026-03-10 ｜ **影响版本**：v0.1.0
> **审批人**：需求方（摄影师本人）

---

## 1. 现象

用户反馈：**软件无法查找到存储卡中的视频文件**。

具体表现（结合代码与复现结论）：插入相机卡后，界面"素材统计"里只有照片，视频数量显示为 0（或只显示少数几个），
实际卡上存在大量 MP4 / MOV / MTS 视频文件；因此这些视频不会被拷贝到服务器。

---

## 2. 复现与证据

### 2.1 复现环境

- 用与真实相机卡相同的目录结构构造"模拟卡"：
  - 照片：DCIM/100CANON/IMG_0001.CR3
  - 视频（与照片同目录）：DCIM/100CANON/MVI_0001.MP4
  - 视频（Sony 结构）：PRIVATE/M4ROOT/CLIP/C0001.MP4、C0002.MP4
  - 视频（Panasonic AVCHD 结构）：AVCHD/BDMV/STREAM/00000.MTS
- 直接调用软件内部同一条扫描代码路径（MediaScanner.Scan），观测统计结果。

### 2.2 复现结果

| 场景 | 扫描路径 | 照片 | 视频 | 结果说明 |
|------|----------|------|------|----------|
| **A（界面实际行为）** | 卡片下的 DCIM 目录 | 1 | **1** | 只找到了 DCIM 内部的 1 个视频；PRIVATE 下 2 个 MP4 与 AVCHD 下 1 个 MTS **完全没有被扫描** |
| B（若从卡根扫描） | 卡片根目录 | 1 | **4** | 照片与 4 个视频全部找到 |
| C（卡上没有 DCIM） | 卡片下的 PRIVATE 目录 | 0 | 2 | 正常找到 2 个视频 |

场景 A 的实际输出（节选）：

```
场景A  界面实际行为：扫描第一个特征目录（DCIM）
  扫描路径: <卡>\DCIM
  照片 1 个 / 视频 1 个 / 其他 0 个；视频字节 8192
  扫描到的文件:
    [Photo] 100CANON\IMG_0001.CR3
    [Video] 100CANON\MVI_0001.MP4
```

**结论**：软件并不是"认不出视频格式"，而是**根本没有去扫描视频所在的那部分目录**。

---

## 3. 根因分析

### 3.1 直接原因：只扫描"第一个特征目录"

三个代码位置构成了一条错误的链路：

| 步骤 | 位置 | 代码行为 | 问题 |
|------|------|----------|------|
| 1 | src/AutoCardCopier.Core/Devices/CardDetector.cs 第 200 行 | 识别卡片时按固定顺序（DCIM → M4ROOT → AVCHD → XDROOT → PRIVATE → BMD …）查找特征目录，**只把第一个命中的目录**记到卡片的 MediaRootPath | 一张 Sony / Panasonic 卡同时有 DCIM（照片）与 PRIVATE、AVCHD（视频）时，MediaRootPath 只能是 DCIM |
| 2 | src/AutoCardCopier.App/ViewModels/Pages/PageViewModels.cs 第 501 行 | 扫描时用 MediaRootPath 作为扫描根 | 扫描范围被压缩成一个子目录 |
| 3 | src/AutoCardCopier.Core/Scanning/MediaScanner.cs 第 154 至 169 行 | 若给定目录下存在特征目录，则**只扫描这些特征目录**，否则才扫描给定目录本身 | 由于传入的已经是 DCIM，PRIVATE / AVCHD 永远不在扫描范围内 |

一句话概括：**"照片在 DCIM、视频在别的顶层目录"这种极其常见的相机结构，会让视频目录整段被跳过。**

### 3.2 为什么有的卡看起来正常

- 视频与照片同放在 DCIM 下（部分佳能、尼康、GoPro、DJI）→ 场景类似 DCIM 内部，能扫到；
- 卡上完全没有 DCIM（纯摄像机卡，视频在 PRIVATE/XDROOT）→ 第一个特征目录就是视频目录，能扫到；
- **只有当卡上同时存在 DCIM 与另一个视频目录时才会暴露**，这正好是 Sony（PRIVATE/M4ROOT）、Panasonic（PRIVATE/AVCHD）、以及"照片 + 摄像"混合拍摄的典型情况。

### 3.3 伴随问题（同一根因的延伸）

1. **特征目录清单不完整**：清单里没有 `CONTENTS`（佳能 XF/XA 专业机的 MXF 目录）、`MP_ROOT`（早期索尼/松下）等；配合 3.1 的"命中即放弃卡根"，这些卡同样会漏；
2. **卡根下的自定义目录被忽略**：只要卡上有任一特征目录，用户自己建的 `VIDEO` 之类目录就不会被扫描；
3. **视频扩展名可再补充**：当前已覆盖 mp4/mov/mxf/braw/r3d/mts/m2ts/avi/mkv/mpg/mpeg/wmv/insv/lrv/crm/m4v/3gp/vob/mod，但缺少 `.ts`、`.m2t`、`.tod`、`.dv` 等老摄像机格式，属于次要问题。

### 3.4 后果链（为什么定级为"严重"）

```
视频目录未被扫描
   → 视频不进入拷贝计划（不会被拷贝）
      → 校验只校验"计划内的文件"，因此全部通过
         → 软件认为"本次拷贝 + 校验已成功"
            → 格式化按钮解锁
               → 用户一旦格式化，未拷贝的视频将被永久删除
```

即：这个缺陷本身只是"漏拷"，但它会让用户误以为素材已经安全备份，从而触发**不可逆的数据丢失**。

## 5. 修复方案

### 5.1 方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|------|------|------|------|------|
| A 最小改动 | 只把 CardDetector 的 MediaRootPath 改成"卡根" | 改动 2 行 | 治标：特征目录清单缺失（CONTENTS 等）与卡根自定义目录仍然会漏 | ❌ 不采用 |
| **B 结构化修复（推荐）** | 卡片识别改为记录**全部**素材根；扫描器改为"特征目录 ∪ 卡根下的其它非忽略目录"；补齐特征目录与扩展名 | 一次性覆盖 Sony/Panasonic/Canon XF/自建目录等全部已知结构 | 需要改动 Core 的 3 个模块 + 补测试 | ✅ **推荐** |
| C 方案 B + 全局兜底 | 在 B 的基础上，再给格式化护栏加一道"扫描覆盖率检查" | 从机制上杜绝"漏扫 + 格式化"组合导致的数据丢失 | 多一次目录比对（开销很小，仅在有卡片时执行） | ✅ **推荐（B+C 一起做）** |

### 5.2 推荐修复内容（B + C）

| 编号 | 修复点 | 涉及文件 | 说明 |
|------|--------|----------|------|
| FIX-1 | 卡片模型记录**多个**素材根（列表），不再只取第一个 | Devices/CardVolume.cs、Devices/CardDetector.cs | 新增 MediaRootPaths；MediaRootPath 保留为兼容属性 |
| FIX-2 | 扫描统一以**卡根**为输入，由扫描器决定实际目录集合 | App/ViewModels/Pages/PageViewModels.cs、Core/Scanning/MediaScanner.cs | 扫描器：特征目录全部扫描 + 卡根下其它非忽略目录也扫描（可用设置开关控制，默认开启） |
| FIX-3 | 补齐特征目录清单：CONTENTS、MP_ROOT、VIDEO、MOVIE 等 | Core/Scanning/MediaScanner.cs、Core/Devices/CardDetector.cs | 与 FIX-2 配合，专业机与老机型也能覆盖 |
| FIX-4 | 补齐视频扩展名：.ts、.m2t、.tod、.dv、.flv、.webm 等 | Core/Scanning/MediaClassifier.cs | 次要但顺手补齐 |
| FIX-5 | **格式化护栏增加扫描覆盖率检查** | Core/Formatting/DiskSafetyInspector.cs、App 层调用处 | 若卡上仍存在"本次未纳入拷贝计划的素材文件"，则拒绝解锁格式化，并提示"卡上还有 N 个素材未被拷贝" |
| FIX-6 | 诊断增强：日志记录实际扫描的根目录与目录清单；界面显示"扫描范围" | MediaScanner.cs、CardsPage/ViewModel | 下次再出现类似问题可一眼定位 |

### 5.3 需要用户确认的两个决策点

1. **FIX-2 的默认行为**：是否接受"除系统与忽略目录外，卡根下的其它目录也一并扫描"（更安全，但可能把用户不想要的杂项目录也纳入统计）？默认建议：**开启**，并在设置中提供开关；
2. **是否需要我先处理已发生的损失**：若某张卡已经执行过格式化，请立即停止对该卡的写入，我可以先给出数据恢复建议，再修 Bug。
