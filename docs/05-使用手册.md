# 自动拷卡助手 · 使用手册

> 适用版本：v0.1（M1–M6 功能已完成，M7 收尾中）
> 配套文档：需求文档（docs/01-需求文档.md）、技术文档（docs/02-技术文档.md）、开发说明（docs/06-开发说明-v0.1.md）

## 1. 它解决什么问题

- 不用再手动在服务器上新建文件夹：软件按“年份 / 日期_拍摄类型_地点”自动建目录；
- 不用再手动复制：插卡后点一次“开始拷贝”，软件并行拷贝并实时显示速度与剩余时间；
- 不用再担心拷坏：拷贝完成后自动校验（默认大小 + 抽样哈希），并生成校验清单；
- 不用再手动格式化：校验通过后可一键快速格式化卡片，且带六道安全护栏；
- 素材自动项目化：每次拍摄都会生成项目记录（时间、地点、类型、机型、文件数、校验状态），可按条件检索。

## 2. 运行环境与安装

| 项目 | 说明 |
|------|------|
| 系统 | Windows 10 1809 及以上 / Windows 11（64 位） |
| 依赖 | 无需安装任何运行时，使用 Windows 自带的 .NET Framework 4.8 |
| 安装方式 | 绿色免安装：把 build\out\Release 目录整体复制到任意位置即可 |
| 体积 | 约 270 KB（3 个文件） |
| 权限 | 不需要管理员权限 |

**第一次运行**：双击 AutoCardCopier.App.exe。程序会自动决定数据目录：

1. 优先使用 %APPDATA%\AutoCardCopier；
2. 如果该位置不可写（例如程序放在只读目录），自动改用程序目录下的 data 文件夹；
3. 两者都不可写时回退到系统临时目录，并在日志中记录。

数据目录中包含：设置（settings.json）、项目库（projects）、任务历史（history.json）、日志（logs）、预设（presets.json）。

## 3. 首次使用（三步）

1. 打开左侧“设置”页，在“素材目标根目录”里填写服务器素材根目录（例如 Z 盘的素材盘根目录，或 UNC 网络路径），点“保存设置”；
2. 确认“命名模板”符合习惯，默认是 {yyyy}/{yyyy-MM-dd}_{type}_{location}，即“年份 / 日期_拍摄类型_地点”；
3. 根据需要在“拷贝与校验”里调整并行数与校验档位（默认并行 4 个文件、校验档位“大小 + 抽样哈希”）。

## 4. 日常拷卡流程

### 4.1 插卡与扫描

1. 插入内存卡（或读卡器）。程序会监听设备插拔，通常 3 秒内识别出卡片；
2. 识别到卡片后会**自动扫描**一次素材，显示照片 / 视频 / 其他文件的数量与体积、素材时间范围、相机型号；
3. 如果没自动识别，点“刷新”；识别到了但没扫描，点“扫描素材”。

> 说明：CFexpress、XQD 读卡器常被 Windows 报成“固定磁盘”，程序通过“是否含 DCIM/M4ROOT/AVCHD 等目录 + 卷标 + 容量”综合判断，不只看“可移动磁盘”标志。

### 4.2 填写拍摄信息

- **拍摄地点**：可以直接输入，也可以从下拉里选历史地点（用过的地点会自动记住并置顶）；
- **拍摄类型**：内置 10 种预设（人像写真、婚纱婚礼、活动会议、商业产品、风光旅行、体育运动、新闻纪实、视频摄制、航拍、其他），也可以直接输入自定义类型；
- **摄影师 / 备注**：可选；
- 右侧“目标目录”会实时显示**将要创建的完整路径**，这就是本次素材的落盘位置。

### 4.3 开始拷贝

点“开始拷贝”，程序依次执行：

1. 生成拷贝计划（每个源文件 → 目标路径，自动按 照片 / 视频 / 其他 分目录）；
2. 预检：目标目录可写、剩余空间不小于素材总量的 1.05 倍；
3. 并行拷贝：显示进度条、实时速度、剩余时间、当前文件；可随时“暂停 / 继续 / 取消”；
4. 校验：按设置的档位比较源与目标；
5. 写入三个自描述文件到项目目录：
   - `_project.json`：项目元数据（拍摄时间、地点、类型、机型、卡号、文件统计、校验状态）；
   - `_manifest.json`：逐文件校验清单（相对路径、字节数、时间、哈希）；
   - `_copy.log`：人类可读的本次拷卡摘要。
6. 写本地项目库与任务历史，并在托盘弹出完成通知；
7. 若在设置中填写了副目标，会再对副目标执行一遍拷贝与校验（详见第 9 章）。

拷贝过程中目标目录**不会出现半截文件**：程序先写临时文件（.acctmp），长度校验通过后才改名成正式文件；取消时临时文件会被清理。

### 4.4 格式化卡片（可选）

**前提**：必须是“本次拷贝并校验通过的那一张卡”，否则按钮不可用。

1. 点“格式化卡片”，确认弹窗（默认文件系统为沿用卡片原有文件系统）；
2. 程序按顺序做六道检查，任意一条不通过都会拒绝执行：
   - 不是系统盘；
   - 不是网络驱动器 / 光驱 / 无根目录卷；
   - 对应物理磁盘不是系统盘所在磁盘；
   - 物理磁盘接口必须是 USB（外接）；
   - 必须存在“拷贝 + 校验通过”的凭证；
   - 卡片指纹必须与刚才校验通过的卡片一致。
3. 通过后调用系统 format.com 执行快速格式化（/Q），并在完成后重新读取卡片信息复核；
4. 失败时会给出可读原因（被占用、写保护、文件系统不支持等）。

如果不想格式化，可以点“清空卡片文件”：只删除素材文件、保留目录结构与文件系统。**两个操作都需要确认，且同样要求校验通过。**

## 5. 项目库

- 每次成功的拷卡都会自动生成一条项目记录；
- 支持按关键词（项目名、地点、备注、机型、类型）搜索，按拍摄类型筛选，列表显示日期、地点、类型、机型、文件数、体积；
- 选中项目后可：打开目录、复制路径、修改拍摄信息（地点 / 类型 / 备注，保存后会同步更新服务器上的 _project.json）、删除记录（只删本地记录，不动素材）；
- “从服务器重建”：扫描目标根目录下若干层里的 _project.json，把项目记录恢复回本地库。换电脑、重装系统后用它即可。

## 6. 历史

- 记录每一次任务：时间、状态（成功 / 部分成功 / 失败 / 已取消）、项目名、文件数、体积、耗时、平均速度、校验状态、失败原因；
- 可打开目标目录或日志目录排查；
- 程序启动时会检测“上次被中断的任务”（例如断电、强制结束进程），提示你重新开始——重新拷贝会自动跳过已经拷好的文件。

## 7. 设置项说明

| 分组 | 项目 | 说明 |
|------|------|------|
| 目标与命名 | 素材目标根目录 | 支持盘符与网络路径 |
| | 命名模板 | 支持 {yyyy} {MM} {dd} {yyyy-MM-dd} {HH} {HHmm} {type} {location} {camera} {photographer} {card} {seq} |
| | 子目录结构 | 不分类 / 按类型 / 按类型与格式（照片再分 RAW 与 JPG） |
| | 目录已存在时 | 自动追加序号（推荐）/ 合并到已有目录 |
| 拷贝与校验 | 并行拷贝文件数 | 1–8，默认 4；机械盘与网络盘建议 2–4 |
| | 校验档位 | 不校验 / 仅大小 / 大小 + 抽样哈希（推荐）/ CRC32 / SHA-256 |
| | 视频也做哈希校验 | 视频体积大，关闭可明显加快校验 |
| 卡片与格式化 | 校验通过后自动格式化 | 默认关闭；开启后仍需人工确认（见“已知简化”） |
| | 自动格式化倒计时秒数 | 记录用户的偏好值 |
| 界面与数据 | 主题 | 浅色 / 深色 / 跟随系统，切换即时生效 |
| | 关闭窗口时最小化到托盘 | 默认开启；真正退出请用托盘菜单 |
| | 开机自动启动 | 写入当前用户启动项 |
| | 日志保留天数 | 默认 90 天 |

## 8. 常见问题

**Q：插卡后没有反应？**
点一次“刷新”。若仍无反应，检查卡片是否被 Windows 正常挂载（资源管理器能看到盘符），或到“关于”页确认数据目录正常。

**Q：目标目录提示不可写 / 空间不足？**
确认网络盘已连接、账号有写权限；空间不足时程序会在拷贝前就阻止并提示所需与可用空间。

**Q：校验失败怎么办？**
失败文件会在“本次结果”里逐条列出。可重新扫描并再次开始拷贝（已一致的文件会跳过）；若同一文件反复校验失败，可能是卡片存在坏块，建议更换卡片或尽快备份。

**Q：能不能对移动硬盘格式化？**
不能。格式化只允许对外接 USB 总线上的、且本次校验通过的卡片执行，这是硬性护栏。

**Q：程序关掉后托盘图标还在？**
程序默认关闭窗口时最小化到托盘（拷卡任务不受影响）。用托盘右键菜单“退出”即可完全退出。

**Q：数据放在哪里？备份哪些？**
默认在 %APPDATA%\AutoCardCopier。建议定期备份 settings.json、projects 目录与 history.json；素材本身在服务器上（每个项目目录自带 _project.json，换机器也能重建项目库）。

## 9. 多目标备份（F11）

1. 打开“设置”，在“素材目标根目录”下方填写“**副目标根目录**”（例如一块移动硬盘的盘符），保存；
2. 之后每次“开始拷贝”会先写主目标，再写副目标，进度区会显示 [1/2]、[2/2] 的目标序号；
3. 每个目标都有**独立的校验**与**独立的 _manifest.json / _project.json**（任意一块盘都能自描述）；
4. 判定规则：
   - 全部目标成功 → 显示“全部 2 个目标均已完成并校验通过”；
   - 某个目标失败（例如移动硬盘没插、空间不足）→ **主目标不受影响**，结果区逐条列出失败原因；
5. 副目标与主目标不能填同一个目录，软件会直接拒绝这种配置。

## 10. 继续上次任务（F12 精确断点续传）

拷卡过程中如果断电、拔卡、强制结束进程，任务状态与逐文件进度会写在数据目录的 tasks 子目录下。

1. 重新打开软件，卡片页会提示“上次任务（xxx）未完成：还剩 N 个文件未拷贝”；
2. **插回原卡**，点击“**继续上次任务**”：
   - 软件直接使用计划文件还原任务，**不需要重新扫描卡片**；
   - 已经确认完成的文件会被跳过（也不会重复校验），只补拷未完成的文件；
   - 补拷完成后重新校验并做覆盖率检查，全部通过后自动删除计划文件；
3. 若源卡片未连接，会明确提示“源卡片未连接（盘符），请插回原卡后再继续”。

> 提示：单个文件失败会自动重试 3 次（间隔 1 秒、3 秒、9 秒）；仍失败的文件会记入失败清单，但不影响其他文件。

## 11. 已知限制（v0.2）

- “校验通过后自动格式化”的倒计时自动执行仍为人工确认（安全优先）；
- 尚无命令行无人值守模式；
- 项目记录的日期范围筛选尚未在界面上开放（底层检索已支持）；
- 多目标为**串行**写入（先主后备），以保证稳定性；
- 视频缩略图、EXIF GPS 自动定位不在本期范围。

详细说明与后续计划见 docs/06-开发说明-v0.1.md 与 docs/09-开发说明-F11多目标与F12精确续传.md。
