## 1. 背景与痛点

现状：一次拷卡只生成**一个项目目录**，拍摄日期取“卡上素材的最早时间”。

实际问题：一张卡里常常装着**连续多天**的拍摄（例如出差三天、婚礼前一天彩排 + 当天正席），
按现状拷完会全部堆在同一个目录里，而且目录名只带**第一天**的日期，后续检索、交付、归档都会错位。

你的诉求：软件自己读出照片/视频的**拍摄日期**，按日期自动切分成多个项目，
然后你在一个界面里**统一填写各项目的项目名**，再一次性拷贝。

---

## 2. 目标

| 编号 | 目标 | 可量化判定 |
|------|------|-----------|
| G1 | 自动识别卡上素材覆盖的拍摄日期，并按下落日期分组 | 一张跨 3 天的卡，扫描后显示 3 个分组，且每组的文件数之和等于卡上素材总数 |
| G2 | 分组可人工命名后再拷贝 | 每个分组可单独填项目名；拷贝后每个分组各生成独立目录，目录名与填写内容一致 |
| G3 | 单日卡片不增加操作负担 | 只检测到 1 个日期时，界面与现有流程一致（不出现分组表格） |
| G4 | 多项目拷贝仍然安全 | 每个项目独立校验与独立清单；全部项目成功且覆盖率通过后才解锁格式化 |

## 3. 功能需求

### F13-A · 拍摄时间提取【P0】

- **功能描述**：扫描素材时，为每个照片与视频读取“拍摄时间”。
- **目的**：分组必须依据真实拍摄时间，而不是拷贝时间或文件系统时间。
- **效果**：
  1. 照片优先读取 EXIF 的原始拍摄时间（DateTimeOriginal），其次数字化时间，再次 EXIF 通用时间；
  2. 视频优先读取容器内的创建时间（MP4/MOV 的 mvhd 盒），读不到时回退到文件修改时间；
  3. 全部读不到时标记为“未知时间”；
  4. 界面上可看到每个文件的拍摄时间来源（用于排查），至少在分组详情里能看到“本组时间来源统计”。
- **验收要点**：对同一批夹具文件，提取结果与预期日期一致；对无 EXIF 的文件回退正确。

### F13-B · 按拍摄日期自动分组【P0】

- **功能描述**：按拍摄时间的“日期”把素材切成若干组，每组对应一个待创建的项目。
- **目的**：把“几天混在一起”的问题在拷贝前解决掉。
- **效果**：
  1. 分组按日期升序排列；
  2. 每组显示：日期、时间范围（最早至最晚）、照片数、视频数、其他文件数、总大小；
  3. 无法确定时间的文件单独成组，名为“未知日期”，并提示需要人工确认；
  4. 支持“日界时间”设置（默认 00:00）：例如设为 04:00 时，凌晨 2 点拍的素材会归到前一天（适合通宵活动）；
  5. 若只有一个日期，界面沿用现有的单项目流程，不显示分组表格。
- **验收要点**：跨午夜拍摄的素材按日界设置归组正确；文件数守恒（各组之和 = 扫描总数）。

### F13-C · 项目信息批量填写【P0】

- **功能描述**：提供一个可编辑的分组表格，你把各项目的名称（以及地点、类型）填好后再开始拷贝。
- **目的**：满足“统一填写各项目名”的诉求，避免拷完再改名。
- **效果**：
  1. 表格列：日期（只读）、时间范围（只读）、文件数/大小（只读）、**项目名**（可编辑）、地点、类型；
  2. 项目名默认按现有命名规则自动生成（日期_类型_地点），可直接改写；
  3. 提供“统一设置”：填写一次地点与类型，一键应用到**全部分组**（也可逐行单独修改）；
  4. 目标目录预览：每个分组实时显示将要创建的完整路径；
  5. 校验：项目名为空、或同一批分组内产生同名目录时，给出提示并阻止开始拷贝；
  6. 支持“重命名规则”：例如自动命名为“日期_类型_地点”或“日期_序号_类型”。
- **验收要点**：修改分组名后拷贝，生成的目录名与填写一致；空名或重名无法开始拷贝。

### F13-D · 多项目拷贝与校验【P0】

- **功能描述**：一次操作把多个分组分别写入各自的项目目录，并逐个校验。
- **目的**：仍然是“点一次就走完”，不因为分组变多而增加重复操作。
- **效果**：
  1. 进度区分两段：当前项目序号（第 2/3 个项目）与项目内文件进度；
  2. 每个项目独立生成校验清单与项目元数据；
  3. 某个项目失败时，**其余项目继续执行**，最后统一汇总（成功 N 个、失败 M 个）；
  4. 全部项目成功且覆盖率检查通过后，才解锁格式化；
  5. 多目标备份同样适用：每个项目在每个目标下各写一份。
- **验收要点**：3 个分组 → 3 个目录、各自清单齐全；人为破坏其中一个文件时，只有该项目被判失败。

### F13-E · 与现有能力的关系【P0】

| 现有能力 | 多日分组下的行为 |
|----------|------------------|
| 命名模板 | 继续生效；日期占位符取**该分组**的日期 |
| 项目元数据与项目库 | 每个分组一条项目记录，可按原有方式检索 |
| 任务历史 | 一次拷贝记一条历史，内含 N 个项目的结果摘要 |
| 多目标备份（F11） | 每个项目 × 每个目标各自写入并校验 |
| 断点续传（F12） | 计划文件覆盖全部分组；续传时按文件状态补齐 |
| 覆盖率护栏与格式化 | 以**全部组**的素材为口径：有任何未覆盖素材或未成功项目，都不解锁格式化 |

### F13-F · 性能与体验【P1】

- 拍摄时间提取必须只读文件头部（照片读前 64 KB 左右、视频读容器头），不得整文件读取；
- 400 个文件的时间提取应在数秒内完成，扫描期间界面可操作、可取消；
- 提取结果缓存到本次扫描结果中，重复扫描同一张卡不重复解析（按需）。

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 准确性 | 同一相机的连续拍摄不能被拆错日期；宁可标为“未知时间”，也不要猜一个错误日期 |
| 可解释 | 每个分组可查看时间来源统计（EXIF / 容器 / 文件时间 / 未知） |
| 兼容 | 单日卡与旧行为一致；旧项目库与清单格式不变 |
| 性能 | 时间提取仅读文件头；有界并发；可取消 |
| 安全 | 格式化解锁条件与现有护栏一致，不因分组而放宽 |

---

## 5. 界面需求（草案）

卡片页在“扫描完成”后：

- 单日：维持现状（拍摄信息表单 + 素材统计 + 开始拷贝）；
- 多日：显示“检测到 N 个拍摄日期”提示 + 分组表格（可滚动）+ 统一设置区 + 每个分组的目标路径预览；
- 表格底部固定“开始拷贝（N 个项目）”按钮，并显示合计文件数与大小。

---

## 6. 数据规范（新增/变化）

| 数据 | 变化 |
|------|------|
| 扫描结果 | 每个文件新增“拍摄时间”与“时间来源”；新增“日期分组”集合 |
| 任务计划文件 | 结构版本升级：一个目标下包含多个分组（项目），每个分组有自己的目录与文件清单 |
| 项目元数据 | 每个分组各写一份，字段不变 |
| 配置 | 新增“日界时间”（默认 00:00）、“时间提取模式”（精确/快速，默认精确） |

| 编号 | 验收项 | 判定方式 |

| A8 | 多目标 + 多项目组合正确 | 断言 |

## 9. 风险与依赖

| 编号 | 风险 | 应对 |
|------|------|------|
| R1 | 部分相机视频容器时间不可靠（厂商写入本地时间而非 UTC） | 分组前在界面展示时间来源与分组结果供你确认；提供“视频按文件时间”开关 |
| R2 | 时区/夏令时导致日期偏移 | 照片按“相机本地时间”直接取日期，不做时区换算；视频若解析 UTC 则换算到本地并标注来源 |
| R3 | 分组过多导致界面拥挤 | 表格虚拟化 + 折叠；超过 20 组时提示 |
| R4 | 时间提取增加扫描耗时 | 只读文件头、有界并发、可切换快速模式 |
| R5 | 与 F11/F12 组合复杂度上升 | 计划文件结构版本化升级；先做单目标多分组，再做多目标多分组 |
