## 2. 实现方式

### 2.1 多目标备份（F11）

```
设置：主目标 + 副目标
   ↓
BackupCoordinator.ResolveTargets   → 校验（不能相同、存在的才纳入）
   ↓
BackupCoordinator.BuildPlans       → 每个目标一份 CopyPlan（项目相对路径一致）
   ↓
BackupCoordinator.RunAsync（串行）
   目标1：预检 → 拷贝（进度带 [1/2] 标记）→ 校验 → 结果
   目标2：同上（目标1 失败不影响目标2，反之亦然）
   ↓
BackupResult：AllSucceeded / AnySucceeded / FailedTargets / Summary
```

设计取舍：

- **串行而不是并行**：两个目标常常在同一块物理盘或同一条网络上，并行会让磁头来回寻道、总体更慢；
- **逐目标独立校验**：避免"主目标校验通过"掩盖"副目标写入失败"；
- **副目标离线不阻塞**：移动硬盘没插时只写 NAS，并在汇总里说明，而不是整个任务失败。

### 2.2 精确断点续传（F12）

```
任务开始：TaskPlanStore.FromPlans → tasks/<taskId>.plan.json（全部文件状态 Pending）
执行中  ：每个文件成功后写入 CopyResult.CompletedTargetPaths
每轮结束：ApplyResult 把 Done/Failed 回写计划文件并保存
异常退出：计划文件保留 → 下次启动 TaskHistoryStore 发现"进行中"任务 → 加载计划文件
继续任务：TaskPlanStore.ToPlans（Done → Skip）→ 协调器执行 → 只补拷未完成文件 → 重新校验
        → 覆盖率通过 → 删除计划文件
```

与旧行为的区别：

| 维度 | v0.1.x（准续传） | v0.2.0（精确续传） |
|------|------------------|--------------------|
| 续传依据 | 目标文件是否存在且大小一致 | 计划文件中的逐文件状态 |
| 是否需要重新扫描卡片 | 需要 | 不需要 |
| 已完成文件是否重复校验 | 会 | 不会（直接跳过） |
| 目标文件被外部改动 | 可能误判为已完成 | 计划文件状态 + 校验兜底 |
| 源卡片未插入时 | 无法继续 | 明确提示"源卡片未连接" |

### 2.3 关键实现细节

1. **时间戳精度**：计划文件中的最后写入时间使用 7 位小数的高精度 ISO 格式（TimeUtil.ToIsoUtcPrecise），
   否则续传后文件时间戳会与源文件产生亚秒级偏差（本次开发中就是被测试用例抓到的）；
2. **UTC 解析**：新增 TimeUtil.ParseIsoUtc，避免把 UTC 时间误当本地时间（同样由测试发现）；
3. **计划文件原子写入**：走 JsonStore.WriteAllTextAtomic，断电也不会写出半个 JSON；
4. **状态集合**：CopyResult 增加 CompletedTargetPaths / FailedTargetPaths，供计划文件回写。

## 6. 使用说明（面向用户）

1. **双备份**：设置页填写"副目标根目录"（例如一块移动硬盘的盘符）→ 之后每次拷贝会先写主目标、再写副目标；
2. **部分成功**：某个目标失败时，结果区会逐条列出原因（例如"副目标 Z 盘未连接"），主目标不受影响；
3. **继续上次任务**：如果拷到一半断电、拔卡或强制关闭程序，重新打开软件后卡片页会提示"还剩 N 个文件未拷贝"，
   插回原卡并点击"继续上次任务"即可直接补拷，不需要重新扫描。
