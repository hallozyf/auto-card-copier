## 执行纪律

1. **先文档后代码（硬性门禁）**：任何新需求都必须先更新需求文档与技术文档，**获得用户明确批准后才可开发**；
   未获批准时只允许编写文档，不得修改任何源码；门禁细则见 docs/00-开发流程与评审门禁.md；
2. **小步提交**：每个步骤一次提交，提交信息遵循规范；
3. **临时文件不落地**：探针、夹具、测试产物一律放系统临时目录或 build 目录，结束后清理；
4. **上下文超过 70%**：主动压缩上下文，把进度与决策写入 AGENT.md 与开发说明；
5. **不提问直接开发**：开发阶段遇到不确定处，按文档与最佳实践自行决策，并在开发说明中记录取舍。
