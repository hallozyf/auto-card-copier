## 1. 背景与四项目标

目前软件已经能"插卡 → 自动建项目 → 拷贝校验"，但素材库本身还缺四件事：

1. **历史素材没有入库**：以前手工整理在服务器上的素材文件夹，软件不认识，项目库里也查不到；
2. **无法往已存在的项目补素材**：同一场拍的第二天补拍、或换了一张卡继续拍，只能新建一个项目，导致同一场拍摄散落在多个目录；
3. **元数据污染素材目录**：当前每个项目目录里都会写入 _project.json、_manifest.json、_copy.log（见现状说明），你希望这些信息只放在软件自己的目录里；
4. **缺少"一场拍摄跨多天"的项目形态**：目前只能按天拆成多个项目，无法把连续几天的拍摄合并成一个项目，也无法选择"合并放一起"还是"按天分文件夹"。

现状事实（已核对源码）：
- 元数据写入位置：src/AutoCardCopier.Core/Copying/ManifestWriter.cs 第 113 至 115 行，直接把 _manifest.json、_project.json、_copy.log 写进项目目录；
- "从服务器重建项目库"功能依赖扫描素材目录里的 _project.json：src/AutoCardCopier.Core/Projects/ProjectLibrary.cs 第 190 至 262 行；
- 项目库本身存在应用数据目录：src/AutoCardCopier.Core/Infrastructure/AppPaths.cs 第 76 行（projects 子目录）。

因此第 3 项需求会**连带影响**"从服务器重建项目库"这个已有功能，本文档与技术文档都会写明替代方案。

## 2. 功能需求

### F14-A · 历史素材库导入【P0】

- **功能描述**：选择一个已有的素材库文件夹，软件自动扫描并识别其中的项目，建立项目库记录。
- **目的**：让以前的素材也能被检索、统计、追加，而不是只服务"新拍的卡"。
- **效果**：
  1. 选择根目录后可设定扫描深度（默认 3 层）；
  2. 软件自动识别"项目文件夹"：包含照片或视频的文件夹层，逐层向下直到最深的素材目录；同一项目的照片/视频/子目录聚合为一条记录；
  3. 每个识别出的项目显示：文件夹名、路径、拍摄日期范围、照片数/视频数、总大小；
  4. 导入前先预览，你可以取消勾选不想入库的项目，也可以修改项目名、地点、拍摄类型；
  5. 已导入过的目录（按路径 + 修改时间判断）不会重复写入，可选择"跳过"或"更新";
  6. 导入后可在项目库中按原有方式检索、打开目录、编辑、追加。
- **验收要点**：对一个真实的旧素材根目录扫描，识别出的项目数量与目录结构一致；重复导入不产生重复记录；文件数之和等于实际素材数。

### F14-B · 向已有项目追加素材（同日期校验）【P0】

- **功能描述**：插卡扫描后，可选择"追加到已有项目"而不是"新建项目"；追加前校验素材日期是否与目标项目匹配。
- **目的**：同一场拍摄分批拷卡时不用散成多个项目。
- **效果**：
  1. 追加目标从项目库里选（可按日期/名称搜索），也可从目标目录里选；
  2. **日期校验**：本次素材的拍摄日期必须落在目标项目的日期范围内（单日项目 = 同一天；跨天项目 = 起始与终止日期之间），否则**禁止追加**并明确提示哪几个文件的日期超出范围；
  3. 文件名冲突处理：同名不同内容 → 自动加序号；同名且大小/哈希一致 → 视为重复，跳过并计入"已存在";
  4. 追加后更新项目记录（文件数、大小、日期范围、更新时间和校验结果）；
  5. 追加同样走校验流程，并只对新追加的文件做校验（已有文件不重复校验）；
  6. 追加完成写一条任务历史，标明"追加"，并记录目标项目。
- **验收要点**：日期不匹配时无法追加且有明确提示；匹配时可追加且原文件不被破坏；重复素材被正确跳过。

### F14-C · 元数据与应用数据外置（不再污染素材目录）【P0】

- **功能描述**：素材目录里不再写入任何软件文件，项目元数据、校验清单与日志全部存放到应用自身的数据目录。
- **目的**：素材目录对客户、对其它软件保持"纯净"。
- **效果**：
  1. 默认不再写入 _project.json、_manifest.json、_copy.log；
  2. 项目库、校验清单、任务日志全部位于应用数据目录（默认 %APPDATA% 下的 AutoCardCopier）；
  3. 提供开关「同时在素材目录写入自描述文件」（默认关闭），用于需要拷走素材后仍可自解释的场合；
  4. 提供迁移工具：扫描指定根目录下的旧 _project.json，导入到应用数据库；
  5. 旧文件处置交由你决定：保留不动（默认）/ 迁移后清理（需二次确认，只删软件自己写的三个文件名）；
  6. 替代能力：原"从服务器重建项目库"改为"从应用数据库恢复 + 从素材目录重新扫描重建"，不依赖素材目录里的 JSON。
- **验收要点**：新拷贝的项目目录里除素材外没有任何软件文件；项目库与清单在应用目录可见；旧项目迁移后检索正常。

### F14-D · 跨多天项目与两种导入布局【P0】

- **功能描述**：可创建"一场拍摄跨多天"的项目，指定起始与终止日期；导入时可选择两种目录布局。
- **目的**：连续几天的拍摄（婚礼三天、旅拍、赛事）应当是一个项目，但目录组织方式要能自己选。
- **效果**：
  1. 项目新增"日期范围"（起始日期、终止日期）；单日项目的起止相同；
  2. 扫描后提供两种模式：
     - **按天拆分**（现有行为）：每天一个项目；
     - **合并为一个项目**：所有天的素材进同一项目，需要你填写起始与终止日期（默认取扫描到的最早与最晚日期）；
  3. 合并模式下可选布局：
     - **布局一（合并放一起）**：项目目录下按类型分 照片 / 视频 / 其他，所有天混放；
     - **布局二（一天一个文件夹）**：项目目录下按日期分 2026-10-03 / 2026-10-04 …，每天内再按类型分 照片 / 视频 / 其他；
  4. 追加素材到跨天项目时，按"日期落在范围内"校验（与 F14-B 一致）；
  5. 项目库列表显示"起止日期"，跨天项目有明确标识。
- **验收要点**：两种布局生成的目录结构与预期一致；跨天项目可多次追加；单日项目行为与现状一致。

## 3. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 导入扫描只读文件元数据（必要时读文件头取拍摄时间），可取消、有进度；10 万个文件量级的根目录不得让界面卡死 |
| 安全 | 导入与追加**只读源、只写目标**；不删除任何素材；清理旧 JSON 必须二次确认且只删软件自身文件名 |
| 一致性 | 应用数据库损坏可重建（从素材目录重新扫描）；写入采用原子写入 |
| 兼容 | 旧版本已生成的项目记录可直接继续使用；旧 _project.json 可一次性迁移 |
| 可解释 | 每个项目的来源（新建/导入/追加）与校验状态可追溯 |

## 6. 本期不做

- 云端素材库与远程索引；
- 项目合并/拆分（把两个已有项目合成一个）——本期只支持"新建时合并"，不支持事后合并；
- 去重扫全库（只做追加时的同名比对）；
- 数据库加密与多用户权限。

## 7. 风险与依赖

| 编号 | 风险 | 应对 |
|------|------|------|
| R1 | 历史目录结构五花八门，"项目"边界难以自动判定 | 导入必须"先预览再写入"，并提供按层级的识别规则说明；允许手动勾选/排除 |
| R2 | 移除外置 JSON 后，素材脱离软件就失去上下文 | 提供默认关闭的"写自描述文件"开关；项目库支持导出清单（可选 CSV） |
| R3 | 追加时同名文件判定 | 先比大小再做哈希比对；哈希模式可选，最快模式下仅比大小并在报告中标注 |
| R4 | 应用数据库随项目增多变大 | 一项目一文件 + 按需加载；清单与项目记录分离存放 |
| R5 | 迁移误删用户文件 | 清理操作只针对三个已知文件名、二次确认、默认不删除 |
